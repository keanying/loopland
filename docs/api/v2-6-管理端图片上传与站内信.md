# 圈圈 Loopland · V2 第六批「管理端图片上传与站内信」API 约定

接第五批（`v2-5-商户商品与开放平台.md`）。通用约定同 `v1.md`；图片存储、类型判断沿用第二批的 App 图片上传（`v2-2-社区.md`「App · 图片上传」）。

## 范围
1. **管理端图片上传**：商品图片、官方活动横幅、场馆封面、商户资质、联名活动横幅、能量商城商品图都改为直接上传（仍可粘贴网址）。
2. **开放平台图片上传**：外部系统上传商品图片后再建商品。
3. **管理端站内信**：商户员工和平台人员在管理端收到与自己相关的通知（审核结果、活动邀请与报名、结算单、开放平台异常等），右上角铃铛显示未读数，可查看全部消息。

## 管理端图片上传

### POST /admin/v1/media（multipart/form-data）
字段：`file`（jpg / png / webp / heic，≤ 10 MB），`purpose`：
- `product` 商品图片（商户员工）
- `promotion_banner` 官方活动横幅（admin、ops）
- `venue_cover` 场馆封面（admin、ops；商户员工只能用于本商户场馆）
- `merchant_license` 商户资质（admin、ops）
- `campaign_banner` 联名活动横幅（admin、ops）
- `shop_item` 能量商城商品图（admin、ops）

→ `{"id": 31, "url": "https://cdn.../product/2026/11/23/xxx.jpg", "width": 1080, "height": 1080}`

- 存储与 App 上传相同：启用对象存储（OSS）时传 OSS，开发环境没启用时存本机并经 `GET /v1/media/files/{path}` 访问；正式环境没启用 OSS 时 503 `media_unavailable`。
- 类型按文件内容判断：不支持 400 `unsupported_media`；超过 10 MB 413 `file_too_large`；`purpose` 取值错误或当前角色不能用 400 `invalid_body` / 403 `forbidden`。
- 每个管理端账号每天最多 500 张，超出 429 `rate_limited`。
- 记录上传者（`admin_id`），商户员工上传的图片记 `merchant_id`。
- 引用校验：商品的 `images`、活动横幅等仍接受任意 https 网址（兼容已有数据和外部图床）；管理端界面默认走上传。

### POST /open/v1/media（scope `products`，签名同开放接口）
- 同上，`purpose` 只能是 `product`；签名时请求体为原始 multipart 字节（待签名串里是它的 SHA256）。
- 记 `merchant_id` 为应用所属商户。

### 数据库
- `src.src_cnt_loop_media`：`user_id` 改为可空，新增 `admin_id`、`merchant_id`、`open_app_id`（三者 / `user_id` 至少一个有值），`purpose_type` 增加上面 6 个取值；字段注释同步更新。

## 管理端站内信

**AdminMessage**：
```json
{
  "id": 88,
  "category": "product | promotion | settlement | openapi | review | system",
  "title": "商品「羽毛球 2 小时畅打套餐」审核通过，已上架",
  "body": "可在「商品」里查看。",
  "link": "/merchant/products?id=31",
  "level": "info | success | warning | error",
  "is_read": false, "read_at": null, "created_at": "..."
}
```

### 接口（所有管理端账号）
- `GET /admin/v1/messages?category=&unread=true&page=` → `{"items":[AdminMessage],"total","unread_count"}`（新的在前）
- `GET /admin/v1/messages/unread-count` → `{"count": 3, "by_category": {"product": 1, "promotion": 2}}`（管理端每 30 秒轮询一次，页面不在前台时暂停）
- `POST /admin/v1/messages/{id}/read` → AdminMessage（只能读自己的，否则 404）
- `POST /admin/v1/messages/read-all` `{"category": "promotion"}`（不传则全部）→ `{"updated": 5}`
- 保留 180 天，每天清理一次。

### 谁收到什么
商户相关的消息发给该商户**所有启用的员工账号**；平台消息发给**所有启用的 admin、ops 账号**（审核类也发给 reviewer）。

| 事件 | 收件人 | category | level | 标题示例 | link |
|---|---|---|---|---|---|
| 商品审核通过 / 自动通过上架 | 商户 | product | success | 商品「X」审核通过，已上架 | `/merchant/products?id=` |
| 商品审核驳回（含自动驳回） | 商户 | product | warning | 商品「X」未通过审核：原因 | 同上 |
| 在售商品的修改审核通过 / 驳回 | 商户 | product | success / warning | 商品「X」的修改已生效 / 未通过 | 同上 |
| 商品被平台强制下架 | 商户 | product | error | 商品「X」已被平台下架：原因 | 同上 |
| 商品进入人工审核 | 平台（含 reviewer） | review | info | 商户「Y」提交了商品「X」，待审核 | `/review?type=product` |
| 平台邀请商品参加活动（待商户同意） | 商户 | promotion | info | 「活动」邀请你的商品「X」参加，活动价 ¥49 | `/merchant/promotions?tab=invites` |
| 平台按原价直接加入活动 | 商户 | promotion | info | 商品「X」已加入「活动」 | `/merchant/promotions?tab=mine` |
| 报名通过 / 驳回 / 被移出 | 商户 | promotion | success / warning / warning | 商品「X」报名「活动」已通过 / 未通过：原因 / 已被移出：原因 | 同上 |
| 商户报名活动（待审核） | 平台 | promotion | info | 商户「Y」报名「活动」：商品「X」 | `/merchant/promotions?id=活动ID` |
| 商户拒绝邀请 / 退出活动 | 平台 | promotion | info | 商户「Y」拒绝了「活动」的邀请 / 退出了「活动」 | 同上 |
| 结算单生成 | 商户 | settlement | info | 第 46 周结算单已生成，待平台确认 | `/merchant/settlement?id=` |
| 结算单确认 / 已付款 | 商户 | settlement | success | 第 46 周结算单已确认 / 平台已付款 ¥1,801.35 | 同上 |
| 平台退款商品订单 | 商户 | product | info | 订单 PO… 已由平台退款 ¥69：原因 | `/merchant/product-orders?id=` |
| 开放平台应用被平台停用 / 启用 | 商户 | openapi | warning / info | 应用「收银系统」已被平台停用 | `/merchant/open-apps` |
| Webhook 投递最终失败（6 次都失败） | 商户 | openapi | error | 应用「收银系统」有 1 条回调推送失败 | `/merchant/open-apps?id=` |
| 同上，24 小时内同一应用只发 1 条 | | | | | |

- 消息在业务事务提交后写入；写消息失败只记日志，不影响业务。
- `title` ≤ 80 字，`body` ≤ 300 字。

### 管理端界面
- 右上角头像旁加铃铛，显示未读数（> 99 显示 99+）；点开是最近 8 条消息的下拉面板（全部 / 未读切换、「全部已读」、「查看全部」），点一条标为已读并跳到 `link`。
- 「消息」页 `/messages`：按分类筛选、只看未读、分页，整页列表样式同其他列表页（卡片占满一屏，表格在卡片里滚动）。
- 商户账号和平台账号都有。

### 数据库
- `src.src_msg_loop_admin_message`：收件人 `admin_id`、`category_type`、`level_type`、`title`、`body_text`、`link_url`、`is_read`、`read_time`、`ref_type` / `ref_id`（来源对象，可空）、`create_time`；索引 `(admin_id, is_read, create_time)`。
