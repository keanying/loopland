# 圈圈 Loopland · V2 第四批「本地生活与商户」API 约定

在 `docs/api/v1.md`、`v2-1-玩法.md`、`v2-2-社区.md`、`v2-3-AI.md` 的基础上增加。通用约定不变（金额单位**分**，坐标 GCJ-02）。

## 范围（功能清单）

| 编号 | 功能 | 本批做什么 |
| --- | --- | --- |
| C-07 | 场馆签到 | 篮球、足球、羽毛球、匹克球、网球、游泳、攀岩、健身房：在场馆范围内定位签到，或扫场馆二维码签到；每次 20 能量（玩法配置）+ 馆主积分；同一场馆每天 1 次 |
| C-08 | 馆主 | 每周（周一 00:00 结算）在某场馆签到积分第一的人成为下一周馆主；地图据点显示馆主头像；合作场馆给馆主订场折扣 |
| E-03 | 场馆预订 | 合作场馆按运动分类、离我多远、时段和价格；选时段下单支付（微信 / 支付宝，iOS 同样走微信 / 支付宝：线下服务不走内购）；馆主折扣；开始前 2 小时可免费取消 |
| D-11 | 球局订场 | 创建约球组局时可以同时订合作场馆的时段 |
| D-12 | 赛事报名费 | 赛事可设报名费，报名即下单支付；开始前取消原路退款 |
| A-16 / E-04 | 联名权益 | 补给站（跑步经过自动领取）、商户宝箱（开宝箱得券）、据点（场馆签到得券）发券；我的卡券包；到店出示二维码，由店员扫码核销；核销需要当天有一条有效运动记录 |
| E-05 | 能量商城 | 用能量换领地皮肤、头像框、地图标记；能量只能运动获得，不能充值、不能转让；已购买的可装备 / 卸下 |
| M-24 | 商户与投放点 | 商户列表（合作中 / 待签约 / 资质审核）、每家的场馆和投放点、今日核销量；商户员工账号 |
| M-25 | 新建投放 | 补给站 / 宝箱 / 据点：位置、权益、每日核销上限、有效期；权益规则在 App 内明示，不设付费抽取 |
| M-26 | 联名活动 | 活动时间、门店数、核销、拉新、商户投入、目标进度；暂停 / 恢复 / 提前上线 |
| M-27 | 核销结算 | 近 7 天核销柱状图；按周生成结算单（核销 + 订场），逐家确认、标记已付款；风控作废的不结算 |
| M-04 | 待处理事项 | 总览的待办加入：待审核商户资质、订场退款申请、待确认结算单 |

不在本批：商户自助入驻后台（本批由运营在管理端录入）、发票、分账（结算单线下打款后标记）。

## 商户与员工（管理端录入）

**Merchant**：
```json
{
  "id": 3, "name": "城南全民健身中心", "type": "venue | brand | store",
  "status": "partner | pending_sign | reviewing | suspended",
  "contact_name": "王经理", "contact_phone": "138****1234",
  "license_images": ["https://..."],
  "booking_commission_rate": 0.1,
  "venue_count": 2, "drop_count": 3, "today_redemptions": 12,
  "created_at": "..."
}
```
- `status`：`partner`-合作中 `pending_sign`-待签约 `reviewing`-资质审核 `suspended`-暂停合作（暂停后其场馆不可预订、投放不再发券、券仍可核销到有效期）。
- `contact_phone` 加密存储，列表脱敏；管理员查看完整号码记审计。
- **商户员工**：管理端账号角色 `merchant`（「商户对接」），创建时绑定 `merchant_id`；只能看到本商户的核销页、核销记录、场馆预订和结算单。

### 管理端接口（角色：admin、ops；`merchant` 只读本商户）
- `GET /admin/v1/merchants?status=&q=&page=` → `{"items":[Merchant],"total"}`
- `POST /admin/v1/merchants`、`PATCH /admin/v1/merchants/{id}` → Merchant
- `GET /admin/v1/merchants/{id}` → Merchant 加 `"venues":[Venue]`、`"drops":[Drop]`、`"staff":[{"id","username","is_disabled"}]`
- `POST /admin/v1/merchants/{id}/staff` `{"username","password"}` → `{}`（建 `merchant` 角色账号并绑定；只有 admin）

## 场馆（C-07、C-08、E-03）

**Venue**：
```json
{
  "id": 8, "merchant": { "id": 3, "name": "城南全民健身中心" },
  "name": "城南全民健身中心 · 匹克球", "sports": ["pickleball", "badminton"],
  "center": { "lat": 31.2, "lng": 121.4 }, "address": "...", "district": "徐汇区",
  "tags": ["室内", "可租拍"], "cover_url": null,
  "checkin_radius_m": 150,
  "bookable": true,
  "price_amt": 6000, "price_unit": "hour",
  "owner": { "user": UserBrief, "points": 120, "since": "2026-11-17" },
  "owner_discount_rate": 0.8,
  "distance_m": 800,
  "my_week_points": 30, "checked_in_today": false
}
```
- `sports` 取值：`basketball` 篮球、`football` 足球、`badminton` 羽毛球、`pickleball` 匹克球、`tennis` 网球、`swimming` 游泳、`climbing` 攀岩、`gym` 健身房。
- `owner` 为本周馆主（没有时 `null`，App 显示「暂无馆主 · 先签到先得」）；`owner_discount_rate` 馆主订场折扣（0.8 = 八折，`null` = 无折扣）。
- `bookable=false` 的场馆只能签到（非合作场馆也可以由运营录入作为签到据点，`merchant` 为 `null`）。

### GET /v1/venues?sport=&lat=&lng=&radius_m=10000&bookable=&cursor= → `{"items":[Venue],"next_cursor"}`（带坐标按距离排序）
### GET /v1/venues/{id} → Venue 加 `"week_rank":[{"rank":1,"user":UserBrief,"points":120}]`（本周积分前 10）
### POST /v1/venues/{id}/checkin
```json
{ "lat": 31.2, "lng": 121.4, "qr": "LPV.8.k3J9x..." }
```
- 二选一：坐标在 `checkin_radius_m` 内，或扫场馆二维码（`qr` 是场馆码内容，服务端验签）。都不满足 400 `checkin_not_allowed`（message 说明原因）；同一场馆当天已签到 409 `already_checked_in`；同一用户每天最多签到 3 个场馆（429 `rate_limited`）。
- 签到生成一条运动记录（`sport=venue`，`unit=checkin`）走原有能量结算（`venue` 每次 20 能量，每日上限照旧），并加馆主积分（每次 10 分，玩法配置 `venue.checkin_points`）；场馆有「据点」投放时发券。
→ `{"activity_id": 120, "energy": 20, "points": 10, "week_points": 40, "coupon": Coupon | null, "venue": Venue}`
- 场馆二维码：管理端「场馆」页下载（内容 `LPV.<venue_id>.<签名>`，签名用服务端密钥，换码即旧码失效）。App 扫码用系统相机或 App 内扫一扫，链接形式 `https://<links.universal_link_domain>/v/<内容>`。

**馆主结算**：每周一 00:00（Asia/Shanghai）按上周各场馆积分第一确定本周馆主（同分先达到者胜），发站内信；馆主头像出现在地图据点上。

### 地图
`GET /v1/map/objects` 新增：
```json
"venues": [ { "id": 8, "name": "...", "center": {..}, "sports": ["pickleball"], "owner_avatar_url": "...", "owner_nickname": "夜跑兔", "bookable": true } ],
"supplies": [ { "id": 4, "name": "补给站 · 瑞幸滨江店", "center": {..}, "radius_m": 80, "perk_title": "美式咖啡 5 折", "claimed_today": false } ]
```

## 订场（E-03、D-11）

**Slot**：`{"start_time":"2026-11-21T18:00:00+08:00","end_time":"...","price_amt":6000,"owner_price_amt":4800,"available":true}`

### GET /v1/venues/{id}/slots?date=2026-11-21 → `{"date":"2026-11-21","items":[Slot]}`
时段由场馆营业时间、时段长度（默认 60 分钟）、场地数和已有预订计算；过去的时段不返回。`owner_price_amt` 只在我是本周馆主时有值。

**Booking**：
```json
{
  "id": 21, "booking_no": "BK20261121183012345", "venue": { "id": 8, "name": "..." },
  "start_time": "...", "end_time": "...", "court_qty": 1,
  "amount_amt": 4800, "original_amt": 6000, "discount_type": "owner | none",
  "status": "pending_pay | paid | cancelled | refunding | refunded | completed | expired",
  "meetup_id": null,
  "pay": { "order_no": "LP...", "channel": "wechat_app" },
  "cancel_deadline": "...", "created_at": "..."
}
```
- `pending_pay` 15 分钟未支付自动 `expired` 并释放时段；`paid` 在开始时间后变 `completed`。

### POST /v1/bookings
```json
{ "venue_id": 8, "start_time": "2026-11-21T18:00:00+08:00", "slots": 2, "channel": "wechat_app | alipay_app | mock", "meetup_id": null }
```
→ `{"booking": Booking, "pay_params": {...}}`（`pay_params` 同会员下单，App 用同一套支付 SDK 拉起）
- 需要实名且成年（未实名 403 `realname_required`，未成年 403 `minor_not_allowed`）；时段已满 409 `slot_unavailable`；连续 1–4 个时段。
- `meetup_id`：给自己发起的约球组局订场，组局详情显示场馆和时段。

### GET /v1/me/bookings?status= → `{"items":[Booking]}`；GET /v1/bookings/{id} → Booking
### POST /v1/bookings/{id}/cancel → Booking
开始前 2 小时以上：全额原路退款（`refunding` → `refunded`）；不足 2 小时：409 `cancel_too_late`（可以联系客服，由管理端退款）。

**支付实现**：订单表 `src.src_ord_loop_order` 增加 `biz_type`（`membership` 会员 / `booking` 订场 / `race_fee` 赛事报名费）和 `biz_id`，`plan_code` 对非会员订单为空；支付回调按 `biz_type` 分发。订场和报名费只支持 `wechat_app` / `alipay_app`（dev 另有 `mock`）。

## 投放与联名权益（A-16、E-04、M-25）

**Perk**（权益，即一张券的模板）：
```json
{ "title": "美式咖啡 5 折", "description": "限滨江店，每人每天 1 次", "value_text": "5 折", "valid_days": 7, "rules": "到店出示券码，店员扫码核销；需要当天有一条运动记录" }
```

**Drop**（投放）：
```json
{
  "id": 4, "merchant": { "id": 5, "name": "瑞幸咖啡" }, "campaign_id": 2,
  "type": "supply | chest | stronghold",
  "name": "补给站 · 瑞幸滨江店",
  "center": { "lat": 31.2, "lng": 121.4 }, "radius_m": 80, "venue_id": null,
  "perk": Perk,
  "daily_cap": 100, "issued_today": 12, "redeemed_today": 5,
  "start_time": "...", "end_time": "...",
  "status": "scheduled | active | paused | ended",
  "settle_price_amt": 200, "settle_direction": "merchant_pays | platform_pays"
}
```
- `supply` 补给站：运动轨迹经过 `radius_m` 范围（运动结算时判定），或人在范围内时点「领取」，得券；每人每个补给站每天 1 张。
- `chest` 商户宝箱：按投放位置刷出宝箱（沿用第一批宝箱机制，深夜不刷），开启得券（宝箱奖励为券而不是能量）。
- `stronghold` 据点：绑定一个场馆（`venue_id`），场馆签到得券。
- `daily_cap`：每天最多发出的券数（发完当天不再发，地图上不显示）。
- `settle_price_amt` / `settle_direction`：每张有效核销的结算单价和方向（商户付给平台的服务费，或平台付给商户的补贴）。
- **不设付费抽取**：所有券只能通过运动、签到免费获得，接口没有任何付费抽券的入口。

**Coupon**（用户的券）：
```json
{
  "id": 77, "code": "8K2D9QXW", "perk": Perk, "merchant": { "id": 5, "name": "瑞幸咖啡" },
  "source": { "type": "supply | chest | stronghold", "drop_id": 4, "name": "补给站 · 瑞幸滨江店" },
  "status": "unused | used | expired | voided",
  "obtained_at": "...", "expires_at": "...", "used_at": null, "used_store": null
}
```

### 运动结算新增
`settlement` 新增 `"coupons": [Coupon]`（本次经过补给站、开商户宝箱得到的券）。

### GET /v1/me/coupons?status=unused|used|expired → `{"items":[Coupon]}`
### POST /v1/drops/{id}/claim `{"lat","lng"}` → Coupon（补给站手动领取；不在范围 400 `too_far`；今天领过 409 `already_claimed`；发完 409 `sold_out`）
### GET /v1/coupons/{id}/qr → `{"payload":"LPC.77.1732180000.Xk2...","expires_in_sec":60}`
到店出示的二维码内容，60 秒有效（防截图转卖），App 每 50 秒刷新一次。

### 核销（商户员工 / 运营）
### POST /admin/v1/redemptions `{"payload":"LPC.77...."}` 或 `{"code":"8K2D9QXW"}`
→ `{"redemption": {"id","coupon": Coupon,"user":{"id","nickname"},"store":"滨江店","created_at"}}`
- 校验：券属于本商户（`merchant` 角色）、未使用未过期、二维码未过期（用 code 手输时不校验二维码时效）、用户**当天**（Asia/Shanghai）有一条已结算且未作废的运动记录（否则 409 `no_activity_today`，message「今天还没有运动记录，运动后再来核销」）、投放当天核销未超 `daily_cap`。
- 错误：`invalid_coupon` 400、`coupon_used` 409、`coupon_expired` 409、`wrong_merchant` 403、`no_activity_today` 409、`daily_cap_reached` 409。
- 核销成功给用户发站内信。
### GET /admin/v1/redemptions?merchant_id=&from=&to=&page= → `{"items":[...],"total"}`
### 风控联动：当天那条运动记录事后被风控作废时，当天依赖它的核销标记 `voided`，不进结算。

## 联名活动（M-26）

**BrandCampaign**：
```json
{
  "id": 2, "merchant": { "id": 5, "name": "瑞幸咖啡" }, "title": "跑完来杯咖啡",
  "description": "...", "cover_url": null,
  "start_time": "...", "end_time": "...",
  "status": "draft | scheduled | running | paused | ended",
  "store_count": 12, "drop_ids": [4, 5],
  "target_redemptions": 5000, "merchant_investment_amt": 2000000,
  "stats": { "issued": 3200, "redeemed": 1800, "new_users": 420, "progress_rate": 0.36 }

```
- `new_users`：活动期间注册、并在注册后 7 天内领到本活动券的用户数。
- 活动的投放跟随活动状态：暂停活动 = 暂停其下所有投放。

### App：GET /v1/brand-campaigns → `{"items":[BrandCampaign 去掉 merchant_investment_amt]}`（进行中的；含每个活动的投放点列表 `"drops":[Drop 的公开字段]`，App 在「联名活动」标签展示规则和领取方式）
### 管理端（admin、ops）
- `GET /admin/v1/brand-campaigns?status=&page=`、`POST`、`PATCH /{id}`
- `POST /admin/v1/brand-campaigns/{id}/pause | resume | launch`（launch = 提前上线，把开始时间改为现在）
- `GET /admin/v1/drops?merchant_id=&type=&status=&page=`、`POST /admin/v1/drops`、`PATCH /admin/v1/drops/{id}`、`POST /admin/v1/drops/{id}/pause | resume`

## 结算（M-27）

**Statement**（结算单，每商户每周一张，周一 03:00 生成上周的）：
```json
{
  "id": 9, "statement_no": "ST2026W46-005", "merchant": { "id": 5, "name": "瑞幸咖啡" },
  "period_start": "2026-11-10", "period_end": "2026-11-16",
  "redemption_qty": 320, "voided_qty": 4,
  "redemption_amt": 64000, "redemption_direction": "merchant_pays",
  "booking_qty": 40, "booking_amt": 240000, "booking_commission_amt": 24000,
  "net_amt": -152000,
  "status": "draft | confirmed | paid",
  "confirmed_by": null, "confirmed_at": null, "paid_at": null
}
```
- `net_amt` 正数 = 商户付给平台，负数 = 平台付给商户（订场款扣佣金后付给商户 + 平台补贴型核销）。
- 风控作废、已退款的不计入。

### 管理端（admin；`merchant` 只读本商户）
- `GET /admin/v1/settlement/overview?days=7` → `{"days":[{"date","redemptions","voided","bookings"}],"pending_statements":3}`（柱状图数据）
- `GET /admin/v1/statements?merchant_id=&status=&page=` → `{"items":[Statement],"total"}`；`GET /admin/v1/statements/{id}` → Statement 加 `"lines":[{"type":"redemption|booking","ref_no","user":{"id","nickname"},"amount_amt","created_at","voided":bool}]`
- `POST /admin/v1/statements/{id}/confirm` → Statement（admin）；`POST /admin/v1/statements/{id}/paid` → Statement（admin，线下打款后标记）
- `POST /admin/v1/statements/generate` `{"period_start":"2026-11-10"}`（admin，手动补生成；已存在则 409）

### 订场管理（admin、ops；`merchant` 只读本商户）
- `GET /admin/v1/bookings?venue_id=&status=&date=&page=` → `{"items":[Booking 加 "user"],"total"}`
- `POST /admin/v1/bookings/{id}/refund` `{"reason"}` → Booking（只有 admin，两次确认在前端做）

### 场馆管理（admin、ops）
- `GET /admin/v1/venues?merchant_id=&sport=&q=&page=`、`POST`、`PATCH /{id}`：可编辑字段 `merchant_id, name, sports, center, address, district, tags, cover_url, checkin_radius_m, bookable, price_amt, slot_minutes, open_time ("07:00"), close_time ("23:00"), court_qty, owner_discount_rate, is_disabled`
- `GET /admin/v1/venues/{id}/qr` → `{"payload":"LPV.8....","url":"https://..."}`；`POST /admin/v1/venues/{id}/qr/rotate` → 同结构（换码）
- `GET /admin/v1/venues/{id}/owners` → `{"items":[{"week_start","user","points"}]}`（历任馆主）

## 能量商城（E-05）

**ShopItem**：
```json
{ "key": "skin_neon", "name": "霓虹领地皮肤", "type": "territory_skin | avatar_frame | map_marker", "price_energy": 800, "image_url": "...", "preview": { "fill": "#D9F26B", "stroke": "#A0D911", "pattern": "grid" }, "description": "...", "owned": false, "equipped": false, "limited_until": null }
```
### GET /v1/shop/items?type= → `{"items":[ShopItem],"energy": 1280}`
### POST /v1/shop/items/{key}/buy → `{"item": ShopItem, "energy": 480}`（能量不足 409 `not_enough_energy`；已拥有 409 `already_owned`；只能用能量，没有任何付费入口）
### POST /v1/shop/items/{key}/equip → ShopItem；DELETE → ShopItem（同类型同时只装备一个）
### 展示
- `UserBrief` 新增可选 `"avatar_frame": "frame_gold"`（装备的头像框 key，App 按 key 画边框；未装备为 `null`）。
- 领地对象（地图、领地详情）新增 `"skin": { "key": "skin_neon", "fill": "#D9F26B", "stroke": "#A0D911", "pattern": "grid" }`（主人装备的领地皮肤；`null` 用默认颜色）。
- `map_marker`：本人在地图上的位置标记样式（`GET /v1/me` 的 `equipped.map_marker`）。
- 管理端（admin、ops）：`GET/POST/PATCH /admin/v1/shop/items`，可上下架、设限时；`GET /admin/v1/shop/stats` → 各商品兑换数和消耗能量。
