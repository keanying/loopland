# 圈圈 Loopland · V2 第五批「商户商品与开放平台」API 约定

接第四批「本地生活与商户」（`v2-4-本地生活与商户.md`）。通用约定（鉴权、错误格式 `{"error":{"code","message"}}`、分页、时间格式、金额单位分）同 `v1.md`。

## 范围

1. **商户商品**：商户在管理端（商户账号）或开放接口自己新建、修改、上下架、删除商品（套餐券、代金券、次卡）；上架前过内容审核。平台（admin、ops）**不新建、不修改**商户商品，只能查看和强制下架。
2. **官方活动**：平台运营做活动（专题、限时活动价），只能用商户**授权**过的商品（商品开关「允许进入官方活动」）；商户也可以把自己的商品**报名**到开放报名的官方活动。活动价由商户让利，平台可加每件补贴。
3. **App 购买**：场馆页、商户页展示在售商品，用户用微信 / 支付宝购买，得到券（进卡券包），到店出示二维码由店员在核销台核销；没用的可退款，过期没用的自动退款。
4. **结算**：商品按**核销**结算给商户（扣平台佣金），并入每周结算单。
5. **商户自助**：商户账号可改自己场馆的部分资料（价格、营业时间、场地数等）。
6. **开放平台**：商户在管理端创建接口凭证，外部系统（收银、ERP、自有订场系统）用签名调用 `/open/v1/*` 管理商品、查订单 / 订场 / 结算、在收银台核销、把线下订场同步过来占场；平台用 Webhook 推送事件。

不做：商品用能量兑换（能量只换装扮）、商品快递发货（全部到店核销）、多规格 SKU（一个商品一个价格）。

## 商户商品

**Product**：
```json
{
  "id": 31, "merchant": { "id": 5, "name": "跑野运动馆" },
  "type": "package | voucher | pass",
  "title": "羽毛球 2 小时畅打套餐", "subtitle": "含球拍租借",
  "description": "周一至周五可用，节假日通用", "images": ["https://..."],
  "sports": ["badminton"],
  "price_amt": 6900, "original_amt": 9000,
  "use_qty": 1,
  "valid_days": 30, "valid_until": null,
  "stock_qty": 200, "sold_qty": 37,
  "per_user_limit_qty": 2,
  "refundable": true,
  "allow_promotion": false,
  "promotion": null,
  "venue_ids": [8, 9], "venues": [{ "id": 8, "name": "跑野运动馆 · 张江" }],
  "rules": "到店出示券码，店员扫码核销",
  "status": "draft | reviewing | on_sale | off_sale | rejected | banned",
  "review_note": null, "has_pending_changes": false,
  "created_at": "...", "updated_at": "..."
}
```
- `type`：`package` 套餐券、`voucher` 代金券（`original_amt` 为面值）、`pass` 次卡（`use_qty` 次，每次核销用掉 1 次，`use_qty` 2–100；其他类型固定 1）。
- 有效期二选一：`valid_days`（购买后 N 天，1–365）或 `valid_until`（固定截止日 `YYYY-MM-DD`，当天 23:59:59 Asia/Shanghai）。
- `stock_qty` 为 `null` 表示不限；`per_user_limit_qty` 为 `0` 表示不限（按已支付且未全额退款的件数算）。
- `allow_promotion`：商户授权平台把该商品选入官方活动（默认 `false`；关掉后不能再被选入，已在进行中的活动不受影响，商户可单独退出）。
- `promotion`：该商品当前生效的官方活动价（App 展示和下单都按它），没有为 `null`：`{"id":3,"title":"双 12 运动狂欢","promo_price_amt":4900,"ends_at":"...","promo_left_qty":80}`（`promo_left_qty` 为活动库存剩余，不限为 `null`）。同一商品同一时间最多在一个生效的活动价里。
- `venue_ids` 为适用门店（本商户的场馆）；空数组 = 本商户所有场馆都可用。
- `price_amt` 1–1,000,000（分）；`original_amt` 可空，填了须 ≥ `price_amt`。`title` 2–40 字，`subtitle` ≤ 40，`description` ≤ 1000，`images` 1–9 张（媒体上传接口拿到的 URL），`rules` ≤ 500。
- App 只返回 `on_sale` 的商品，且不返回 `status`、`review_note`、`has_pending_changes`、`stock_qty`（改为 `"sold_out": bool`）。

### 状态流转
- 新建 → `draft`；`POST .../submit` → 内容审核（沿用 `moderation` 模块：敏感词 + AI，任务类型 `product`）：低风险自动通过 → `on_sale`；高风险自动驳回 → `rejected`（`review_note` 写原因）；中间进人工审核队列（`reviewing`），管理端「内容审核 → 审核队列」处理。
- `on_sale` → `off-sale`（商户下架）→ `off_sale`；`off_sale` → `on-sale` 直接上架（内容没变时不再审核）。
- 在售商品改**内容字段**（`title / subtitle / description / images / rules`）：改动先存为待审版本（`has_pending_changes: true`），旧内容继续在售；审核通过后替换，驳回则丢弃并写 `review_note`。改**其他字段**（价格、库存、限购、有效期、门店、退款）立即生效（只影响之后的购买）。
- 平台强制下架 → `banned`（必填原因，写入 `review_note`；商户不能自行上架，只能修改后重新提交审核）。
- `rejected` 可修改后重新提交。
- 删除：从未卖出的直接删除；卖出过的改为归档（列表不再显示，已售出的券照常可用）。
- 商户暂停合作（`suspended`）时其商品在 App 不可见、不可购买。

### 商户 / 平台管理端（`/admin/v1`）
商户账号只能看和改本商户的商品；平台 `admin`、`ops` 可看全部（`merchant_id=` 筛选、`allow_promotion=true` 筛选可选品），只能强制下架，不能新建、修改、上下架、删除（403 `forbidden`）。
- `GET /admin/v1/products?merchant_id=&status=&q=&allow_promotion=&page=` → `{"items":[Product],"total"}`（不含归档）
- `POST /admin/v1/products` → Product（`draft`；仅商户账号）
- `GET /admin/v1/products/{id}` → Product 加 `"pending": {...待审内容字段} | null`
- `PATCH /admin/v1/products/{id}` → Product（只改传了的字段）
- `DELETE /admin/v1/products/{id}` → 204
- `POST /admin/v1/products/{id}/submit` → Product（`draft` / `rejected` / `banned` 可提交，其他 409 `invalid_status`）
- `POST /admin/v1/products/{id}/on-sale`、`/off-sale` → Product（状态不对 409 `invalid_status`）
- `POST /admin/v1/products/{id}/ban` `{"reason"}` → Product（仅 admin、ops）
- `GET /admin/v1/product-orders?merchant_id=&product_id=&status=&from=&to=&page=` → `{"items":[ProductOrder 加 "user":{"id","nickname"}],"total"}`
- `POST /admin/v1/product-orders/{id}/refund` `{"reason"}` → ProductOrder（仅 admin；退未使用的券）
- 权限：`product.read`（admin、ops、merchant）、`product.write`（仅 merchant）、`product.ban`（admin、ops）、`product_order.refund`（admin）。
- 审计：新建、修改、提交、上下架、删除、强制下架、退款都记审计日志。

### App（`/v1`）
- `GET /v1/venues/{id}` 新增 `"products": [Product]`（适用该场馆的在售商品，最多 10 个，按销量）。
- `GET /v1/merchants/{id}/products?cursor=` → `{"items":[Product],"next_cursor"}`
- `GET /v1/products/{id}` → Product 加 `"my_bought_qty": 1`（下架、封禁、归档的返回 404 `not_found`）
- `POST /v1/products/{id}/orders` `{"qty":1,"channel":"wechat|alipay|mock"}` → `{"order": ProductOrder, "pay_params": {...}}`（同订场的支付参数；`mock` 仅 dev）。商品有生效的活动价时按活动价下单，订单记 `promotion_id`；活动库存不足 409 `sold_out`。
  - 错误：`sold_out` 409（库存不足）、`limit_reached` 409（超过限购）、`not_on_sale` 409、`qty` 1–10 否则 400 `invalid_request`。
  - 下单即锁库存，15 分钟未支付自动取消并释放（同订场）。
- `POST /v1/product-orders/{id}/pay` → 同上（继续支付）；`POST /v1/product-orders/{id}/cancel` → ProductOrder（未支付才能取消）
- `GET /v1/me/product-orders?status=` → `{"items":[ProductOrder]}`；`GET /v1/product-orders/{id}` → ProductOrder
- `POST /v1/product-orders/{id}/refund` → ProductOrder（退所有未使用的券；`refundable=false` 409 `not_refundable`；没有可退的 409 `nothing_to_refund`）

**ProductOrder**：
```json
{
  "id": 120, "order_no": "PO20261122103000012",
  "product": { "id": 31, "title": "...", "type": "package", "image": "https://..." },
  "merchant": { "id": 5, "name": "跑野运动馆" },
  "qty": 2, "unit_price_amt": 6900, "amount_amt": 13800, "refund_amt": 0,
  "refundable": true,
  "promotion": null,
  "status": "pending | paid | completed | refunding | refunded | cancelled",
  "coupons": [Coupon],
  "pay_expires_at": "...", "paid_at": null, "created_at": "..."
}
```
- `paid`：已支付，还有未使用的券；`completed`：券全部用完 / 过期且不可退；`refunded`：全部退款完成（部分退款保持 `paid` / `completed`，`refund_amt` 累计）。
- 支付成功后每件发 1 张券。
- `promotion`：按活动价买的为 `{"id","title"}`。

## 官方活动（平台运营）

**Promotion**：
```json
{
  "id": 3, "title": "双 12 运动狂欢", "subtitle": "羽毛球、游泳、健身 5 折起",
  "banner_url": "https://...", "description": "...",
  "starts_at": "...", "ends_at": "...",
  "apply_open": true, "apply_deadline": "...",
  "status": "draft | scheduled | active | ended | cancelled",
  "product_qty": 12, "created_at": "..."
}
```
**PromotionEntry**（活动里的一个商品）：
```json
{
  "id": 40, "promotion_id": 3, "product": Product, "merchant": { "id": 5, "name": "跑野运动馆" },
  "promo_price_amt": 4900, "platform_subsidy_amt": 500, "promo_stock_qty": 100, "promo_sold_qty": 20,
  "sort_no": 0,
  "source": "platform | merchant",
  "status": "pending_merchant | pending_platform | active | rejected | withdrawn | removed",
  "note": "", "created_at": "...", "decided_at": null
}
```
- **平台选品**（`source=platform`）：只能选 `allow_promotion=true`、在售的商品。`promo_price_amt` 等于商品原价（或不填）→ 直接 `active`；低于原价 → `pending_merchant`，商户同意后 `active`、拒绝 `rejected`。
- **商户报名**（`source=merchant`）：活动 `apply_open=true` 且未过 `apply_deadline` 时，商户把自己在售的商品报名（可填 `promo_price_amt` ≤ 原价、`promo_stock_qty`）→ `pending_platform`，运营通过 → `active`（可同时设 `platform_subsidy_amt`）、驳回 → `rejected`（`note` 写原因）。商户报名不要求打开 `allow_promotion`。
- 商户随时可退出（`withdrawn`）；平台可移除（`removed`，必填原因）。已售出的不受影响。
- 活动价在活动 `active` 期间、条目 `active`、活动库存没卖完时生效；同一商品同一时间只能有一个 `active` 且时间重叠的条目（冲突 409 `promotion_conflict`）。
- `platform_subsidy_amt`：平台每卖出（核销）一件补给商户的金额，进结算（见下）。
- 商品被封禁、归档或商户暂停合作时，条目不再生效。
- 活动、条目的每次状态变化都给商户发站内信（管理端顶部消息）并推送 Webhook（`promotion_entry.*`）。

### 管理端
平台（`promotion.manage`：admin、ops）：
- `GET /admin/v1/promotions?status=&page=`、`POST`、`GET /{id}`、`PATCH /{id}`、`POST /{id}/publish`（draft → scheduled / active）、`POST /{id}/cancel`
- `GET /admin/v1/promotions/{id}/entries?status=` → `{"items":[PromotionEntry]}`
- `POST /admin/v1/promotions/{id}/entries` `{"product_id","promo_price_amt","platform_subsidy_amt","promo_stock_qty","sort_no"}` → PromotionEntry（平台选品；商品没授权 409 `not_authorized`）
- `POST /admin/v1/promotion-entries/{id}/approve` `{"platform_subsidy_amt"}`、`/reject {"note"}`、`/remove {"note"}`、`PATCH {sort_no, platform_subsidy_amt}` → PromotionEntry
商户（`promotion.join`：merchant）：
- `GET /admin/v1/promotions?apply_open=true` → 可报名的活动；`GET /admin/v1/promotion-entries?status=` → 本商户的条目（含平台邀请）
- `POST /admin/v1/promotions/{id}/apply` `{"product_id","promo_price_amt","promo_stock_qty"}` → PromotionEntry
- `POST /admin/v1/promotion-entries/{id}/accept`、`/decline {"note"}`、`/withdraw` → PromotionEntry
- 商品编辑页有「允许进入官方活动」开关（`allow_promotion`）。

### App
- `GET /v1/promotions` → `{"items":[Promotion]}`（进行中和即将开始的）；`GET /v1/promotions/{id}` → Promotion 加 `"items":[Product]`（生效条目的商品，`promotion` 字段为本活动价，按 `sort_no`）
- 首页「玩法」/ 本地生活入口展示进行中的官方活动横幅。

### 券（Coupon）扩展
商品券和投放券共用卡券包、二维码、核销台：
- `source.type` 新增 `"product"`，此时 `source` 为 `{"type":"product","product_id":31,"order_id":120,"name":"羽毛球 2 小时畅打套餐"}`；`perk` 由商品生成（`title`、`description`=subtitle、`value_text`=价格文案、`rules`）。
- 新增 `"uses_total": 1, "uses_left": 1`（次卡 > 1）；`status` 新增 `"refunded"`。
- 商品券**不要求当天有运动记录**（花钱买的），也不受投放 `daily_cap` 限制；核销时校验门店：传了 `store` 或核销账号绑定的场馆不在 `venue_ids` 内时 403 `wrong_store`（`venue_ids` 为空不校验）。
- **员工绑定门店**：商户员工账号可以绑定本商户的一个或多个场馆（`src.src_mer_loop_staff_venue`；不绑定 = 不限门店）。绑定了门店的员工核销商品券时：券的适用门店（`venue_ids`，空 = 本商户全部门店）和他的门店没有交集 → 403 `wrong_store`；传了 `store` 必须是两者都允许的门店；不传时，允许的门店只有一个就记为它，否则记商户名。开放平台核销不受员工绑定影响。
  - `POST /admin/v1/merchants/{id}/staff` 可带 `"venue_ids":[...]`；`PUT /admin/v1/merchants/{id}/staff/{staff}/venues` `{"venue_ids":[...]}`（仅 admin，空数组 = 解除绑定）→ Staff；不是本商户的场馆 400 `invalid_body`。
  - 商户详情里的 Staff 为 `{"id","username","is_disabled","venue_ids":[8],"venues":[{"id":8,"name":"跑野运动馆 · 张江"}]}`。
- 次卡每次核销 `uses_left - 1`，到 0 变 `used`；每次核销一条 Redemption。
- 过期未使用：`refundable=true` 的自动退款（每天 02:00 任务），券 `refunded`；否则 `expired`。

### 结算
- 结算单新增 `"product_qty"`（周期内商品券核销次数）、`"product_amt"`（对应的实付金额，次卡按 实付单价 ÷ 次数 四舍五入到分）、`"product_commission_amt"`（= round(product_amt × 商户 `product_commission_rate`)）、`"product_subsidy_amt"`（官方活动的平台补贴，按核销计）。
- `net_amt = 核销轧差 − (booking_amt − booking_commission_amt) − (product_amt − product_commission_amt) − product_subsidy_amt`。
- 明细 `lines[].type` 新增 `"product"`。
- 商户新增字段 `product_commission_rate`（0–1，默认 0.08；管理端「商户」编辑页可改，仅 admin）。
- 退款不进结算；已核销的不能退。

## 商户自助改场馆
- 商户账号 `PATCH /admin/v1/venues/{id}`（本商户的场馆）只能改：`cover_url, tags, price_amt, slot_minutes, open_time, close_time, court_qty, owner_discount_rate, bookable`（关闭订场 = 临时停订，已有订单不受影响）。传其他字段 403 `field_not_allowed`。位置、半径、名称、所属商户等仍由平台改。
- 权限 `venue.self`（merchant）；管理端「场馆」页对商户账号可见，只显示本商户场馆。

## 开放平台（`/open/v1`）

### 凭证（OpenApp）
每个商户可建最多 5 个应用：
```json
{
  "id": 3, "app_id": "lpa_7f3k2m9x", "name": "收银系统",
  "scopes": ["products", "orders", "bookings", "redemptions", "statements", "venues", "promotions"],
  "ip_allowlist": ["203.0.113.10"],
  "webhook_url": "https://pos.example.com/loopland/webhook",
  "webhook_events": ["product_order.paid", "redemption.created"],
  "status": "active | disabled",
  "last_used_at": null, "created_at": "..."
}
```
- 管理端（商户账号管本商户；admin 可看全部、可停用）：
  - `GET /admin/v1/open-apps?merchant_id=` → `{"items":[OpenApp]}`
  - `POST /admin/v1/open-apps` `{"name","scopes","ip_allowlist","webhook_url","webhook_events"}` → OpenApp 加 `"app_secret": "..."`（**只在创建和重置时返回一次**）
  - `PATCH /admin/v1/open-apps/{id}` → OpenApp；`DELETE` → 204
  - `POST /admin/v1/open-apps/{id}/reset-secret` → OpenApp 加 `app_secret`（旧密钥立即失效）
  - `POST /admin/v1/open-apps/{id}/disable`、`/enable` → OpenApp
  - `GET /admin/v1/open-apps/{id}/calls?page=` → 最近 7 天调用记录 `{"items":[{"id","method","path","status_code","error_code","latency_ms","ip","created_at"}],"total"}`
  - `GET /admin/v1/open-apps/{id}/deliveries?page=` → Webhook 投递记录 `{"items":[{"id","event_id","event_type","status":"pending|succeeded|failed","attempt_qty","last_status_code","last_error","next_retry_at","created_at"}],"total"}`
  - `POST /admin/v1/open-apps/{id}/deliveries/{did}/redeliver` → 投递记录（立即重发一次）
  - `POST /admin/v1/open-apps/{id}/test-webhook` → 投递记录（发一条 `ping` 事件）
  - 权限 `openapi.manage`（admin、merchant）；`app_secret` 加密存库（数据加密密钥），不明文落日志；所有操作记审计。
- 商户暂停合作或应用停用时，接口返回 403 `app_disabled`，Webhook 停发。

### 签名
每个请求带：
```
X-Loop-App-Id: lpa_7f3k2m9x
X-Loop-Timestamp: 1732240000          # Unix 秒，与服务器相差不超过 300 秒
X-Loop-Nonce: 6f1c0a9e2b7d4c31        # 16–64 位随机串，10 分钟内不可重复
X-Loop-Signature: <hex(HMAC-SHA256(app_secret, 待签名串))>
```
待签名串（`\n` 连接）：
```
METHOD
/open/v1/products
a=1&b=2              # query 参数按 key 字典序排序后 urlencode 拼接；没有为空行
1732240000
6f1c0a9e2b7d4c31
<hex(SHA256(请求体原始字节))>   # 没有请求体时为空串的 SHA256
```
- 错误：缺头 / 签名不对 401 `invalid_signature`；时间戳超范围 401 `timestamp_expired`；nonce 重复 401 `nonce_reused`；`app_id` 不存在 401 `invalid_app`；IP 不在白名单 403 `ip_not_allowed`；没有对应 scope 403 `scope_denied`；限流（每个应用每分钟 120 次）429 `rate_limited`（带 `Retry-After`）。
- 幂等：`POST` 可带 `Idempotency-Key`（≤ 64 字符，24 小时内同 key 返回第一次的结果）。处理中同 key 再请求返回 409 `idempotency_conflict`；第一次请求出错（5xx）或服务异常中断时这个 key 立即释放，可以用同一个 key 重试；「处理中」状态最多保持 2 分钟（服务进程意外退出也不会把 key 锁 24 小时）。
- 所有接口只操作凭证所属商户的数据，访问别家的返回 404 `not_found`。
- 调用记入调用日志（保留 7 天），不记请求体。
- 文档里附 Go、Java、Python、Node 的签名示例（见文末）。

### Webhook
- 事件：`product.reviewed`（审核结果）、`promotion_entry.invited`（平台邀请商品参加活动，待商户同意）、`promotion_entry.approved`、`promotion_entry.rejected`、`promotion_entry.removed`、`product_order.paid`、`product_order.refunded`、`booking.paid`、`booking.cancelled`、`booking.refunded`、`redemption.created`、`redemption.voided`、`statement.created`、`ping`。
- 请求：`POST webhook_url`，`Content-Type: application/json`，body：
  ```json
  { "id": "evt_01JD...", "type": "product_order.paid", "created_at": "2026-11-22T10:30:00+08:00", "merchant_id": 5, "data": { ...对应对象，同开放接口返回结构 } }
  ```
  头：`X-Loop-Event`、`X-Loop-Delivery`（投递 id）、`X-Loop-Timestamp`、`X-Loop-Signature: hex(HMAC-SHA256(app_secret, timestamp + "." + body))`。
- 对方 10 秒内返回 2xx 算成功；否则按 1 分钟、5 分钟、30 分钟、2 小时、6 小时重试，共 6 次，之后标记 `failed`（可在管理端手动重发）。同一事件 `id` 可能重复投递，接收方按 `id` 去重。
- 只推送订阅了的事件（`webhook_events`）且应用有对应 scope 的。
- 生产环境 `webhook_url` 须为 https，且解析到内网 / 本机 / 链路本地地址时拒绝投递（记为失败，`last_error` 说明原因），防止借回调访问平台内部服务；开发环境不限制，方便本机联调。

### 签名示例（Python）
```python
import hashlib, hmac, time, secrets, requests
def call(method, path, query="", body=b""):
    ts, nonce = str(int(time.time())), secrets.token_hex(8)
    s = "\n".join([method, path, query, ts, nonce, hashlib.sha256(body).hexdigest()])
    sig = hmac.new(APP_SECRET.encode(), s.encode(), hashlib.sha256).hexdigest()
    h = {"X-Loop-App-Id": APP_ID, "X-Loop-Timestamp": ts, "X-Loop-Nonce": nonce, "X-Loop-Signature": sig, "Content-Type": "application/json"}
    return requests.request(method, BASE + path + ("?" + query if query else ""), data=body, headers=h)
```
`query` 要和实际发送的一致：参数按 key 字典序排列、`application/x-www-form-urlencoded` 编码（空格为 `+`，同 Python `urlencode`、Go `url.Values.Encode()`）。

### 签名示例（Go）
```go
func sign(secret, method, path, query string, body []byte) (ts, nonce, sig string) {
	ts = strconv.FormatInt(time.Now().Unix(), 10)
	b := make([]byte, 8)
	_, _ = rand.Read(b)
	nonce = hex.EncodeToString(b)
	sum := sha256.Sum256(body)
	s := strings.Join([]string{method, path, query, ts, nonce, hex.EncodeToString(sum[:])}, "\n")
	m := hmac.New(sha256.New, []byte(secret))
	m.Write([]byte(s))
	return ts, nonce, hex.EncodeToString(m.Sum(nil))
}
```

### 签名示例（Java）
```java
static String hex(byte[] b) { StringBuilder s = new StringBuilder(); for (byte x : b) s.append(String.format("%02x", x)); return s.toString(); }
static String sign(String secret, String method, String path, String query, String ts, String nonce, byte[] body) throws Exception {
    String bodyHash = hex(MessageDigest.getInstance("SHA-256").digest(body));
    String s = String.join("\n", method, path, query, ts, nonce, bodyHash);
    Mac mac = Mac.getInstance("HmacSHA256");
    mac.init(new SecretKeySpec(secret.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
    return hex(mac.doFinal(s.getBytes(StandardCharsets.UTF_8)));
}
```

### 签名示例（Node）
```js
const crypto = require('crypto');
function sign(secret, method, path, query, body = '') {
  const ts = String(Math.floor(Date.now() / 1000)), nonce = crypto.randomBytes(8).toString('hex');
  const s = [method, path, query, ts, nonce, crypto.createHash('sha256').update(body).digest('hex')].join('\n');
  return { ts, nonce, sig: crypto.createHmac('sha256', secret).update(s).digest('hex') };
}
```

def verify(headers, raw_body):
    expect = hmac.new(APP_SECRET.encode(), (headers["X-Loop-Timestamp"] + ".").encode() + raw_body, hashlib.sha256).hexdigest()

## 后端实现说明（与上文的补充和澄清）

以下是后端落地时补充的细节，前端按这里对接；上文没有提到的字段都是**新增**，原有字段和错误码不变。

### 商品
- `POST /admin/v1/products` 必填 `type`、`title`、`images`、`price_amt` 和有效期（`valid_days` / `valid_until` 二选一）；`PATCH` 里 `original_amt`、`stock_qty`、`valid_days`、`valid_until` 传 `null` 表示清空（`stock_qty: null` = 不限）。校验失败 400 `invalid_body`；`venue_ids` 只能是本商户的场馆。卖出过的商品不能改 `type`。
- 提交审核（`submit`、内容改过后的 `on-sale`）先进入 `reviewing`，低风险当场变 `on_sale`，高风险当场 `rejected`；所以接口返回的 `status` 可能是三者之一。审核中的商品改内容会撤回原审核任务并重新送审。
- 在售商品的待审改动被驳回时，商品仍在售，`review_note` 写驳回原因；`GET /admin/v1/products/{id}` 的 `pending` 为待审的完整内容（`title / subtitle / description / images / rules`）。
- 下架后改了内容再 `on-sale` 需要重新审核；`banned` 时待审改动作废。
- 删除：有过任何订单（含未支付）的商品归档（`DELETE` 同样返回 204）。
- `venues`：`venue_ids` 对应的场馆；`venue_ids` 为空时列出本商户全部场馆。
- 限购按 待支付 + 已支付（未全额退款）的件数算，防止多开待支付订单绕过限购。退款不退回库存。
- 内容审核队列里商品任务 `target_type=product`、`target_id` 为商品 ID、`user` 为 `null`；`text` 为标题、副标题、说明、规则拼接，`images` 为商品图。

### 商品订单
- ProductOrder 新增 `"pay": {"order_no": "LP...", "channel": "wechat_app"}`（同 Booking；dev 环境用 `POST /v1/dev/orders/{order_no}/pay` 模拟支付）。下单 `channel` 也接受 `wechat_app` / `alipay_app`。
- 支付超时沿用玩法配置 `booking.pay_timeout_min`（默认 15 分钟）；`POST /v1/product-orders/{id}/pay` 只对未超时的 `pending` 订单有效，否则 409 `invalid_status`。超时 / 取消后到账的钱自动原路退款。
- 退款按次部分退款（每次一个退款单，渠道失败时订单保持 `refunding`，后台每分钟重试）；次卡用过部分次数时，只退剩余次数对应的金额（实付 − 已核销次数 × round(实付 ÷ 次数)）。
- 「订单」页的通用退款 `POST /admin/v1/orders/{no}/refund` 不能退商品订单（409 `use_product_refund`，避免把已核销的券也退掉），请用 `POST /admin/v1/product-orders/{id}/refund`。
- 用户收到站内信：购买成功、退款到账、核销（次卡写剩余次数）。

### 券与核销
- 商品券的 `source` 没有 `drop_id`（投放券不变）。`GET /v1/me/coupons?status=refunded` 可查已退款的券；已退款的券取二维码 409 `coupon_refunded`，核销 400 `invalid_coupon`。
- 门店校验：`store` 与券的适用门店（`venue_ids`）里某个场馆的名称或 ID 一致才能核销，否则 403 `wrong_store`；不传 `store` 时，只有一个适用门店就记为它，否则记商户名称。核销账号目前不绑定场馆，所以只校验 `store`。
- Redemption 的 `activity_id` 对商品券为 `null`。`POST /open/v1/redemptions` 直接返回 Redemption（管理端仍是 `{"redemption": Redemption}`）。

### 官方活动
- `POST /admin/v1/promotions` 体：`title`（2–40 字）、`subtitle`、`banner_url`、`description`、`starts_at`、`ends_at`、`apply_open`、`apply_deadline`；新建为 `draft`，`PATCH` 只改传了的字段（改时间若与已生效条目冲突 409 `promotion_conflict`）。已结束的活动不能发布 / 取消（409 `invalid_status`）。
- 草稿活动里也可以先选品；同一活动里同一商品只能有一个未结束的条目（409 `entry_exists`）。活动未开放报名、已过截止时间时报名 409 `apply_closed`；商品不在售 409 `not_on_sale`；活动价高于售价 400 `invalid_body`。
- `GET /admin/v1/promotions` 对商户账号只返回已发布、未结束的活动（`GET /{id}` 对草稿为 404）；`GET /admin/v1/promotions/{id}/entries` 仅平台；`GET /admin/v1/promotion-entries` 平台可用 `promotion_id`、`merchant_id` 筛选全部条目。
- `platform_subsidy_amt`、活动价都在下单时记入订单；次卡的补贴按次数分摊进结算（同金额）。
- **站内信**：管理端目前没有面向后台账号的站内信，活动 / 条目状态变化暂只推送 Webhook（`promotion_entry.*`），商户在「官方活动 → 平台邀请 / 我的报名」查看状态；后台消息上线后再补。

### 结算
- 结算单明细 `lines[]` 新增 `"subsidy_amt"`（这次核销对应的官方活动补贴，非商品明细为 0）；`type=product` 的 `amount_amt` 为这次核销对应的实付金额。投放券的 `redemption_qty / redemption_amt` 不含商品券。
- `merchant` 的 `product_commission_rate` 只有 admin 能改（ops 传这个字段 403 `forbidden`），新建商户默认 0.08。

### 场馆
- 商户账号 `GET /admin/v1/venues`、`GET /admin/v1/venues/{id}` 只看到本商户场馆（别家 404）；新建场馆、二维码、历任馆主仍只给平台。
- 新增 `GET /admin/v1/venues/{id}/blocks?date=` → `{"items":[Block]}`：「场馆预订」页显示外部占场（商户账号只能看本商户场馆）。
- 占场：`court_qty` 默认 1；不对齐时段或超出营业时间 400 `invalid_slot`，日期格式错 400 `invalid_date`，已结束的时段 400 `invalid_slot`。

### 开放平台
- OpenApp 新增 `"merchant": {"id","name"}`；新增 `GET /admin/v1/open-apps/{id}`。创建、修改、删除、重置密钥、发测试事件只能商户账号（平台账号 403 `forbidden`）；平台可查看、停用、启用、重发。被平台停用的应用商户不能自行启用（403 `forbidden`）。每个商户最多 5 个应用（409 `app_limit`）。
- `webhook_url` 须为 `https://`（dev 环境允许 `http://`），`webhook_events` 取上文事件（不含 `ping`），`ip_allowlist` 可写 IP 或 CIDR。
- 签名校验顺序：缺头 → `app_id` → 时间戳 → nonce 长度 → 签名 → nonce 重复 → 应用停用 → IP → 限流 → scope。`Idempotency-Key` 重放的响应带 `Idempotent-Replayed: true`；同一个 key 的第一个请求还在处理时 409 `idempotency_conflict`；5xx 结果不缓存。
- 游标分页的 `next_cursor` 为本页最后一条的 ID（字符串），没有下一页为 `null`。`GET /open/v1/products?page=` 按页（同管理端 `{"items","total"}`），`GET /open/v1/products/{id}` 同管理端详情（含 `pending`）。
- `GET /open/v1/venues` → `{"items":[Venue（管理端结构）]}`；`GET /open/v1/promotions` → `{"items","total"}`（只含已发布未结束的）；`GET /open/v1/promotion-entries` → `{"items"}`。

### Webhook
- `product.reviewed` 的 `data` 为 `{"result": "approved | rejected", "note": "驳回原因", "product": Product}`；其他事件的 `data` 为对应对象（ProductOrder、PromotionEntry、Booking、Redemption、Statement（含明细））。`ping` 的 `data` 为 `{"message":"pong","app_id"}`。
- 事件产生后几秒内投递；对方返回非 2xx 或 10 秒无响应即失败，按 1 分钟、5 分钟、30 分钟、2 小时、6 小时重试，第 6 次失败标记 `failed`。手动重发失败的投递不会重新进入重试队列。应用停用或商户暂停合作时，待投递的记录直接标记 `failed`。
- 投递不跟随重定向。
