# 圈圈 Loopland · V2 第二批「社区」API 约定

在 `docs/api/v1.md`、`docs/api/v2-1-玩法.md` 的基础上增加。通用约定（鉴权、错误格式、分页、坐标 GCJ-02、时间 RFC3339）不变。

## 范围（功能清单 D-01 ~ D-13、E-01、M-01、M-16）

| 编号 | 功能 | 本批做什么 |
| --- | --- | --- |
| D-01 | 社区首页 | 聚合接口：我的跑团卡片、未读消息数、即将开始的组局/集结跑、进行中的赛事 |
| D-02 | 动态流 | 关注 / 推荐两个标签；推荐可在设置里关闭个性化（按时间排序） |
| D-03 | 互动 | 点赞、评论、收藏、分享（记分享次数，返回分享链接和海报数据）、关注作者 |
| D-04 | 动态详情与评论 | 完整轨迹（隐藏起终点）；评论两级（评论 + 回复），评论可点赞；举报 |
| D-05 | 发布动态 | 文字 ≤ 500 字、图片 ≤ 9 张，可附一次运动；可见范围公开/仅粉丝/仅跑团/仅自己；默认隐藏起终点 200 m；先过审核 |
| D-06 | 轨迹回放 | 回放流接口（上下滑）返回轨迹点，App 端做 15–30 秒竖屏动画；会员可导出 1080p（App 端判断权益 `hd_replay_export`） |
| D-07 | 他人主页 | 资料、关注/粉丝/获赞、累计里程、领地、图鉴数、动态；关注、私信、拉黑 |
| D-08 | 跑团 | 已有；本批补「邀请码加入」，跑团名称和头像改为先发布后审核 |
| D-09 | 跑团排行 | 已有（`week_rank`） |
| D-10 | 集结跑 | 团长发起时间地点，成员报名；到场签到；签到满 2 人后这次运动的合击伤害、能量各 +20%（玩法配置可调） |
| D-11 | 组局 | 约跑/约球/约骑：时间、地点、人数、要求；报名即进群聊；附近组局列表。订场馆在第④批 |
| D-12 | 赛事 | 线上赛（时间窗内单次运动跑满距离即完赛，可要求穿戴设备数据）、线下赛报名；完赛发奖牌。报名费在第④批 |
| D-13 | 消息 | 分类（互动 / 领地 / 怪兽 / 系统）和未读数；私信、群聊。推送通道（厂商推送）和深夜免打扰在接入推送时做 |
| E-01 | 我的 | 关注 / 粉丝 / 获赞数（走他人主页接口传自己的 id） |
| M-01 | 总览 | 「待审核」数 |
| M-16 | 内容审核 | 动态、评论、跑团名称、跑团头像、用户昵称、用户头像六类，按风险分排序；举报处理；敏感词配置 |

## 通用对象

**UserBrief**（所有出现「用户」的地方）：
```json
{ "id": 7, "nickname": "阿梅", "avatar_url": "https://...", "crew": { "id": 3, "name": "城西跑团" } }
```
`crew` 没有跑团时为 `null`。已注销用户显示 `"nickname": "已注销用户"`，`avatar_url: null`。

**Cursor 分页**（动态流、评论、消息这类无限下拉的列表）：请求 `?cursor=<上一页返回的 next_cursor>&limit=20`（limit 最大 50），返回 `{"items":[...],"next_cursor":"..."}`，没有更多时 `next_cursor` 为 `null`。cursor 是不透明字符串，App 原样回传；无法识别的 cursor 返回 400 `invalid_cursor`（从头加载即可）。

**审核状态 `review_status`**：`pending`-待审核（只有作者自己能看到，带「审核中」标记） `approved`-已通过 `rejected`-未通过（只有作者自己能看到，带原因）。

## 内容审核规则（后端统一）

发布动态、评论、私信/群聊消息、组局标题和说明、改昵称、改跑团名称时，后端先做文本风险打分（0–100）：

| 命中 | 分数 |
| --- | --- |
| 敏感词「拦截」级（管理端配置） | 100：直接拒绝，返回 400 `content_blocked`（message 说明原因，不回显敏感词） |
| 敏感词「审核」级 | 70 |
| 手机号、微信号、QQ 号、网址等联系方式 | 50 |
| 新用户（注册不满 24 小时）发布带图片的动态 | +20 |
| 其他 | 0 |

- 动态、评论：分数 < `auto_approve_below`（默认 30，第三批起默认 20 并增加自动拦截线，见 `v2-3-AI.md`；管理端「敏感词与审核设置」可调）直接通过；否则进入审核队列，状态 `pending`。
- 私信、群聊消息：分数 ≥ 70 拒绝发送（400 `content_blocked`）；其他直接发送。
- 昵称、头像、跑团名称、跑团头像：**先生效后审核**，全部进入审核队列；审核拒绝时恢复为默认值（昵称恢复为默认昵称「圈圈 + 运动描述」，按用户固定，如「圈圈晨跑侠」；跑团名「跑团+id」、头像清空）并发站内信。
- 第三批接入 AI 后，打分换成 AI + 敏感词，接口不变。

## App · 图片上传

### POST /v1/media（multipart/form-data）
字段：`file`（jpg/png/webp/heic，≤ 10 MB），`purpose`：`post`-动态图片 `avatar`-用户头像 `crew_avatar`-跑团头像 `chat`-聊天图片。

→ `{"id": 12, "url": "https://cdn.../post/2026/11/21/xxx.jpg", "width": 1080, "height": 1440}`

- 存储：管理端「系统配置」里启用「对象存储 OSS」后传到阿里云 OSS；没启用时（开发环境）存本机 `server/data/media/`，通过 `GET /v1/media/files/{path}` 访问。
- 动态、头像等只能引用**本人上传**的图片 url，否则 400 `invalid_media`。
- 每人每天最多上传 200 张，超出 429 `rate_limited`。
- 类型按文件内容判断（不看文件名和 Content-Type）：不是 jpg/png/webp/heic 时 400 `unsupported_media`；超过 10 MB 413 `file_too_large`；`purpose` 取值错误 400 `invalid_body`。
- `width`/`height` 是显示尺寸（jpg 已按 EXIF 方向换算）；heic 读不出尺寸时为 `null`。
- 正式环境没启用 OSS 时 503 `media_unavailable`。

## App · 关注、拉黑、他人主页

### GET /v1/users/{id} → Profile
```json
{
  "user": { UserBrief },
  "bio": "每天 5 公里",
  "follower_count": 120, "following_count": 30, "like_received_count": 860,
  "total_distance_m": 1203400, "territory_count": 12, "territory_area_m2": 304000, "codex_count": 23,
  "post_count": 18,
  "relation": { "following": true, "followed_by": false, "blocked": false, "blocked_by": false },
  "is_self": false
}
```
- 被对方拉黑（`blocked_by`）时仍返回资料，但动态列表为空、不能关注和私信。
- `bio`：用 `PATCH /v1/me {"bio":"..."}` 修改（≤ 60 字，走昵称同样的审核）；没填时为 `""`。
- 已注销或不存在的用户 404。`like_received_count` = 动态获赞 + 评论获赞。

### PATCH /v1/me（本批变化）
`{"nickname":"...","avatar_id":12,"bio":"...","settings":{...}}` → `User`（`User` 增加 `bio` 字段）
- 昵称、头像、简介**先生效后审核**：保存后立即生效并进入审核队列（`nickname` / `avatar` / `bio`）；命中拦截词 400 `content_blocked`；拒绝时恢复默认值（昵称恢复为默认昵称「圈圈 + 运动描述」，如「圈圈晨跑侠」；头像清空、简介清空）并发互动类站内信（`data.type=review_rejected`）。
- `avatar_id` 必须是本人上传的图片（否则 400 `invalid_media`）。旧字段 `avatar_url` 仍可用：`""` 清除头像，其他值必须是本人上传图片的 url。
- `bio` 传 `""` 清空（不送审）；超过 60 字 400 `invalid_bio`。禁言中改昵称、头像、简介 403 `muted`。

### GET /v1/users/{id}/posts?cursor= → `{"items":[Post],"next_cursor"}`（按可见范围过滤）
### POST /v1/users/{id}/follow → `{"following": true}`；DELETE → `{"following": false}`
- 不能关注自己（400 `invalid_target`）；任一方拉黑对方时 403 `blocked`；重复关注原样返回。
- 被关注时给对方发互动类站内信（同一人 24 小时内重复关注只发一次）。
### GET /v1/users/{id}/followers?cursor= 、/following?cursor= → `{"items":[{"user":UserBrief,"following":bool,"followed_at":"..."}],"next_cursor"}`
（`following` 表示我是否关注了这个人）
### POST /v1/users/{id}/block → `{}`；DELETE → `{}`
拉黑后互相取消关注；互相看不到对方的动态和评论；不能私信。不能拉黑自己（400 `invalid_target`）。
### GET /v1/me/blocks → `{"items":[{"user":UserBrief,"blocked_at":"..."}]}`

## App · 动态

### Post 对象
```json
{
  "id": 101,
  "author": { UserBrief },
  "content": "今天绕世纪公园圈了一大块",
  "images": [ { "url": "https://...", "width": 1080, "height": 1440 } ],
  "activity": {
    "id": 55, "sport": "run", "distance_m": 5230, "duration_sec": 1820, "pace_sec_per_km": 348,
    "claimed_area_m2": 32000, "start_time": "...",
    "track": [[121.5, 31.2], [121.51, 31.21]]
  },
  "visibility": "public | fans | crew | private",
  "review_status": "approved", "reject_reason": null,
  "like_count": 12, "comment_count": 3, "collect_count": 1, "share_count": 0,
  "liked": false, "collected": false,
  "created_at": "..."
}
```
- `activity` 没附运动时为 `null`。`track` 是 `[lng, lat]` 数组，已抽稀到 ≤ 300 点，并按作者设置**去掉起点和终点 200 m 内的点**（`settings.hide_endpoints`，默认开）。列表里同样返回轨迹（用于缩略图），详情一样。
- 作者本人看到 `pending` / `rejected` 的动态；其他人只看到 `approved`。
- 可见范围：`fans` 是关注了作者的人；`crew` 是**当前**与作者在同一跑团的成员；`private` 只有作者。拉黑关系的双方互相不可见。

### POST /v1/posts
```json
{ "content": "...", "image_ids": [12, 13], "activity_id": 55, "visibility": "public" }
```
→ `Post`（`review_status` 为 `approved` 或 `pending`）
- `content` 1–500 字（去掉首尾空白；有图片或运动时可为空）；`image_ids` ≤ 9；`activity_id` 必须是自己已结算的运动；`visibility` 默认 `public`；选 `crew` 时必须在跑团里（否则 400 `not_in_crew`）。
- 禁言中（`mute_end_time` 未到）403 `muted`。每人每天最多 20 条（玩法配置 `community.daily_post_limit`，删除的也算），超出 429 `rate_limited`。
- 错误：正文超长或为空 400 `invalid_content`；超过 9 张或引用别人的图片 400 `invalid_media`；运动不是自己已结算的 400 `invalid_activity`。

### DELETE /v1/posts/{id} → `{}`（作者删除）
### GET /v1/posts/{id} → `Post`（不可见时 404）
### GET /v1/feed?tab=following|recommend&cursor= → `{"items":[Post],"next_cursor"}`
- `following`：我关注的人 + 我自己的动态，按时间倒序。
- `recommend`：近 7 天公开且已通过的动态，按热度（点赞×2 + 评论×3 + 收藏×2 + 1）÷（小时数 + 2）^1.5 排序；用户设置 `settings.personalized=false` 时按时间倒序。排除拉黑关系。
### POST /v1/posts/{id}/like → `{"liked":true,"like_count":13}`；DELETE → `{"liked":false,...}`
### POST /v1/posts/{id}/collect → `{"collected":true,"collect_count":2}`；DELETE 取消
### GET /v1/me/collections?cursor= → `{"items":[Post],"next_cursor"}`
### POST /v1/posts/{id}/share `{"channel":"wechat | moments | poster | link"}`
→ `{"share_count": 1, "url": "https://<links.share_base>/p/101", "poster": {"title":"...","subtitle":"5.23 km · 5'48\"","image_url":"..."}}`
（分享链接的 H5 页面不在本批；`share_base` 取后端配置 `http.public_base_url`）
`poster.title` 取正文前 30 字（没有正文时为「昵称 的动态」），`subtitle` 没附运动时为 `""`，`image_url` 取第一张图片，没有图片时为 `null`。`channel` 取值错误 400 `invalid_body`。

### 评论

**Comment 对象**：
```json
{
  "id": 9, "post_id": 101, "author": { UserBrief }, "content": "厉害",
  "reply_to": { UserBrief } , "parent_id": null,
  "like_count": 2, "liked": false, "review_status": "approved",
  "reply_count": 3, "replies": [ Comment ],
  "created_at": "..."
}
```
- 两级：`parent_id` 为空是一级评论；回复的 `parent_id` 是一级评论 id，`reply_to` 是被回复的人（回复一级评论时为 `null`）。
- 一级评论里带最早的 3 条回复（`replies`），更多用 `/replies` 翻页；回复对象里 `replies` 为 `[]`、`reply_count` 为 0。

### GET /v1/posts/{id}/comments?cursor= → `{"items":[Comment],"next_cursor"}`（一级评论，按时间正序）
### GET /v1/comments/{id}/replies?cursor= → `{"items":[Comment],"next_cursor"}`
### POST /v1/posts/{id}/comments `{"content":"...","parent_id":9,"reply_to_user_id":7}` → `Comment`
- 1–200 字（否则 400 `invalid_content`）；对动态不可见时 403 `forbidden`，和动态作者（或被回复的人）有拉黑关系时 403 `blocked`；禁言 403 `muted`；每人每分钟最多 5 条（429 `rate_limited`）。
- `parent_id` 必须是这条动态下的一级评论（否则 400 `invalid_parent`）；`reply_to_user_id` 只在回复时有效，必须是这条一级评论或它下面某条回复的作者。
- 审核规则同动态：分数 < `auto_approve_below` 直接通过，否则 `pending`（只有作者自己能看到）。
- 通过审核后给动态作者（以及被回复的人）发互动类站内信（同一个人只发一条：被回复的人就是动态作者时只发 `reply`）。
- `comment_count` / `reply_count` 只计已通过、未删除的评论。
### DELETE /v1/comments/{id} → `{}`（评论作者或动态作者可删，否则 403 `forbidden`；删一级评论时它的回复一起删除）
### POST /v1/comments/{id}/like → `{"liked":true,"like_count":3}`；DELETE 取消

### 举报
### POST /v1/reports
```json
{ "target_type": "post | comment | user | crew | message", "target_id": 101, "reason": "spam | porn | abuse | fraud | illegal | other", "detail": "可选，≤ 200 字" }
```
→ `{"id": 5}`。同一人对同一对象只能举报一次（重复返回同一个 id）。被 3 个不同用户举报（管理端设置 `report_auto_hide`）的动态/评论自动转为 `pending` 等审核（审核任务的 `report_count` 为举报人数）。
不能举报自己的内容（400 `invalid_target`）；对象不存在 404（`message` 不在这里校验）。

## App · 轨迹回放

### GET /v1/replays?cursor= → `{"items":[Replay],"next_cursor"}`
公开且已通过、附了运动的动态，按推荐顺序（同推荐流）。
```json
{
  "post_id": 101, "content": "动态正文（自己没发动态的运动为空字符串）", "author": { UserBrief },
  "activity": { "id": 55, "sport": "run", "distance_m": 5230, "duration_sec": 1820, "claimed_area_m2": 32000 },
  "points": [ { "lng": 121.5, "lat": 31.2, "t": 0 }, { "lng": 121.51, "lat": 31.21, "t": 35 } ],
  "like_count": 12, "liked": false
}
```
`points` 抽稀到 ≤ 600 个，`t` 为相对第一个点（去掉起点 200 m 之后）的秒数，已去掉起终点 200 m（`community.hide_endpoints_m`，作者关了 `hide_endpoints` 时不去）。App 按 15–30 秒压缩播放。

### GET /v1/activities/{id}/replay → 同上的单条（只能看自己的运动，或附在自己可见的动态里的运动，否则 404）
`post_id`、`like_count`、`liked` 取附了这次运动、我能看到的最新一条动态；自己的运动没发动态时 `post_id` 为 `null`、`like_count` 为 0。

## App · 私信与群聊

**Conversation**：
```json
{
  "id": 4, "type": "direct | group",
  "title": "周六世纪公园约跑", "avatar_url": null,
  "peer": { UserBrief },
  "ref": { "type": "meetup | rally", "id": 8 },
  "last_message": { Message }, "unread_count": 2, "muted": false, "peer_read_message_id": 75,
  "updated_at": "..."
}
```
`direct` 有 `peer`，`title` 为对方昵称；`group` 的 `peer` 为 `null`，`ref` 指向来源（组局或集结跑），否则为 `null`。

**Message**：
```json
{ "id": 77, "conversation_id": 4, "sender": { UserBrief }, "type": "text | image | post | system", "content": "几点集合？", "payload": {}, "created_at": "..." }
```
`image` 的 `payload`：`{"url","width","height"}`；`post`（分享动态）：`{"post_id":101}`；`system`：进群、退群等，`sender` 为 `null`。

### GET /v1/conversations?cursor= → `{"items":[Conversation],"next_cursor"}`（按最后消息时间倒序）
### GET /v1/conversations/{id} → `Conversation`（不是成员 403 `not_member`）
`peer_read_message_id`：私信里对方已读到的消息 id（群聊为 0），用来显示「已读」；之后靠 `conversation_read` 事件更新。
### POST /v1/conversations/direct `{"user_id": 7}` → `Conversation`（已存在就返回原来的）
- 拉黑关系 403 `blocked`。对方没关注我时，对方回复前我最多发 3 条，超出 403 `stranger_limit`。
### GET /v1/conversations/{id}/messages?before=<message_id>&limit=30 → `{"items":[Message],"next_cursor"}`（倒序翻历史；`next_cursor` 是更早一条的 id 字符串）
### POST /v1/conversations/{id}/messages `{"type":"text","content":"...","image_id":12,"post_id":101}` → `Message`
文本 1–500 字；每人每分钟最多 30 条；被拉黑、已退出群、禁言时 403。
### POST /v1/conversations/{id}/read `{"message_id": 77}` → `{}`
### POST /v1/conversations/{id}/mute `{"muted": true}` → `{}`
### DELETE /v1/conversations/{id} → `{}`（私信：从列表隐藏，直到有新消息；群聊：退出群，组局报名同时取消）

- 不在会话里（含已退出的群）403 `not_member`；会话不存在 404。给自己发私信 400 `invalid_target`。
- `unread_count`：别人发的（含系统消息）、id 大于我已读位置的消息数。新进群的人从进群那一刻算起。免打扰（`muted`）的会话照常有 `unread_count`，但不计入 `GET /v1/inbox/summary` 的 `chat`。
- `system` 消息的 `payload`：`{"event":"join | leave | cancelled","user_id":7}`（`cancelled` 没有 `user_id`）。
- 文本先过审核规则（分数 ≥ 70 拒绝，400 `content_blocked`）；`image` 用 `image_id` 引用本人上传的图片（否则 400 `invalid_media`）；`post` 引用存在且未删除的动态（否则 404）。每人每分钟 30 条，超出 429 `rate_limited`。

实时：WebSocket 新增事件 `{"type":"chat_message","message":Message}` 和 `{"type":"conversation_read","conversation_id":4,"user_id":7,"message_id":77}`。

## App · 组局

**Meetup**：
```json
{
  "id": 8, "type": "run | ball | ride", "title": "周六世纪公园约跑", "description": "配速 6 分左右，跑 10 公里",
  "start_time": "...", "end_time": "...",
```

## App · 集结跑（跑团）

**Rally**：
```json
{
  "id": 5, "crew": { "id": 3, "name": "城西跑团" }, "creator": { UserBrief },
  "title": "周三夜跑", "start_time": "...", "place": { "name": "徐家汇公园", "lat": 31.19, "lng": 121.43 },
  "distance_goal_m": 5000, "status": "open | cancelled | ended",
  "joined_count": 6, "checked_in_count": 4, "joined": true, "checked_in": false,
  "bonus_active": true, "conversation_id": 9, "created_at": "..."
}
```

### GET /v1/crews/{id}/rallies → `{"items":[Rally]}`（未结束的在前，最近 30 天）
### POST /v1/crews/{id}/rallies `{title,start_time,place:{name,lat,lng},distance_goal_m}` → `Rally`（团长；同一跑团同时最多 3 个未结束的集结跑；创建后通知全体成员）
- 非团长 403 `not_leader`；超过 3 个 409 `rally_limit`；开始时间须在 30 天内的将来；标题 1–30 字（命中拦截词 400 `content_blocked`）。通知是互动类站内信，`data.type=rally_created`，带 `rally_id`、`crew_id`。
- `GET` 列表只有跑团成员能看（否则 403 `not_in_crew`）。
### POST /v1/rallies/{id}/join → `Rally`；/leave → `Rally`；/cancel（团长）→ `Rally`
（报名须是该跑团成员，403 `not_in_crew`；已取消或已结束 409 `rally_closed`；发起人不能退出 409 `creator_cannot_leave`；取消非团长 403 `not_leader`）
### POST /v1/rallies/{id}/checkin `{"lat":31.19,"lng":121.43}` → `Rally`
在开始前 30 分钟到开始后 60 分钟内、离集合点 ≤ 300 m（`rally.checkin_radius_m`）才能签到，且须先报名（否则 400 `checkin_not_allowed`，message 说明原因）。

开始 3 小时后集结跑状态变为 `ended`。

**加成**：签到人数 ≥ 2（`rally.min_checkins`，`bonus_active=true`）时，签到成员在「开始时间 ~ 开始后 3 小时」内结算的运动（按运动的**结束时间**判断，离线晚传、人工复核后结算也算；签到人数在结算时计）：合击伤害（运动造成的怪兽伤害）和获得能量各乘以 `1 + rally.bonus_rate`（玩法配置，默认 0.2）。结算结果新增字段：
```json
"rally": { "id": 5, "bonus_rate": 0.2 }
```
没有加成时为 `null`。能量先加成再计每日上限（`energy_raw` 是加成后的值）；圈地的攻击强度不加成。

集结跑同样建群聊（跑团成员报名即入群）。

## App · 赛事

**Race**：
```json
{
  "id": 2, "type": "online | offline", "title": "城市 10K 线上赛", "cover_url": "...", "description": "...",
  "sport": "run", "distance_m": 10000,
  "start_time": "...", "end_time": "...", "signup_end_time": "...",
  "place": { "name": "...", "lat": 31.2, "lng": 121.4 },
  "capacity": 5000, "signed_count": 1200,
  "requires_wearable": true,
  "medal": { "key": "race_2026_city10k", "name": "城市 10K 完赛奖牌", "image_url": "..." },
  "status": "upcoming | signup | running | finished | cancelled",
  "my_entry": { "status": "signed | finished | dnf", "result_sec": 3120, "finished_at": "...", "rank": 35 }
}
```
- `status` 由时间计算：报名截止前 `signup`；开始前 `upcoming`（已截止报名）；进行中 `running`；结束 `finished`；运营取消 `cancelled`。报名截止时间可以晚于开始时间（线上赛边跑边报），这段时间 `status` 为 `running`，仍可报名。
- `my_entry.status`：赛事结束时仍未完赛的显示为 `dnf`。`rank` 按 `result_sec` 升序（同成绩先完赛的在前），线下赛由运营录入成绩后同样有排名。
- `place` 线上赛为 `null`；`my_entry` 未报名为 `null`；`rank` 线上赛按用时排名。

### GET /v1/races?status=&cursor= → `{"items":[Race],"next_cursor"}`
### GET /v1/races/{id} → `Race`（加 `"leaderboard":[{"rank":1,"user":UserBrief,"result_sec":2400}]` 前 50）
### POST /v1/races/{id}/signup → `Race`（截止或满员 409 `signup_closed` / `race_full`；报名费第④批接支付）
### DELETE /v1/races/{id}/signup → `Race`（开始前可取消，开始后 409 `race_started`）

**线上赛完赛判定**（运动结算时自动做）：已报名、运动类型匹配、运动开始和结束都在赛事时间窗内、单次运动距离 ≥ `distance_m`；`requires_wearable=true` 时这次运动必须带穿戴设备数据（`wearable`）。完赛：记录用时（按距离折算到赛事距离），发奖牌（图鉴 `medal` 类，`item` = `medal.key`）和站内信。一场赛事只算第一次完赛。结算结果新增：
```json
"races": [ { "id": 2, "title": "城市 10K 线上赛", "result_sec": 3120, "medal": { ... } } ]
```
没有完赛时为 `[]`。
线下赛的完赛由运营在管理端标记（`POST /admin/v1/races/{id}/entries/{user_id}/finish`）。

完赛站内信是互动类，`data.type=race_finished`，带 `race_id`。奖牌出现在 `GET /v1/codex` 的 `medals` 里：`{"key":"race_2026_city10k","name":"城市 10K 完赛奖牌","type":"race","image_url":"...","progress":1,"target":1,"obtained":true,"obtained_at":"..."}`（只列已获得的）。

### POST /admin/v1/reports/{id}/handle `{"action":"remove | dismiss","mute_days":0,"note":""}` → `{}`
`remove`：下架对象（动态/评论删除、用户昵称/头像/简介和跑团名称/头像恢复默认），同一对象的其他举报一起处理；`dismiss` 同样一起驳回同一对象的其他待处理举报；`mute_days>0`（≤ 365）时禁言作者（跑团为团长）。
