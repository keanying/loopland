# 圈圈 Loopland · 数据库与命名规范

参照文旅项目的表规范，按运动类业务改写。**所有新建表、字段、SQL 都必须遵守**；代码评审时按本文检查。

## 一、命名风格

- 全小写 + 下划线（snake_case）。
- 不允许拼音，只用英文单词或本文列出的缩写。
- **表名**：`分层_业务域_loop_实体名[_粒度]`。`loop` 是本项目（圈圈 Loopland）的项目标识，固定放在业务域之后，用来和其他项目的表区分（共用数仓、共用实例时一眼能看出归属）。例：`src.src_act_loop_activity`（运动记录，业务源表）、`dws.dws_act_loop_user_sport_di`（用户运动天汇总）。**所有分层都要加**，测试会检查 `src` 库的表名必须匹配 `src_<业务域>_loop_<实体>`。
- **字段名**：`实体_属性`，例：`order_no`、`territory_id`、`start_time`。
- **代码中一律写「库(schema).表」**，例：`SELECT * FROM src.src_usr_loop_user`，不写裸表名。
- **每张表、每个字段都必须有注释**（`COMMENT ON TABLE / COLUMN`）。测试会检查 `src` 库里有没有缺注释的表或字段。
- **类型、状态类字段必须在注释里写清每个取值的含义**，例：`状态：active-正常 banned-封禁 deleting-注销冷静期 deleted-已注销`。

## 二、数据分层（schema 与表前缀）

| 层级 | schema | 含义 | 表前缀 |
| :--- | :--- | :--- | :--- |
| SRC | `src` | 业务源层：线上业务库（后端直接读写的表） | `src_` |
| ODS | `ods` | 原始数据层：从业务库、日志、埋点原样同步 | `ods_` |
| DWD | `dwd` | 明细层：清洗、规范化 | `dwd_` |
| DWS | `dws` | 汇总层：主题宽表 | `dws_` |
| ADS | `ads` | 应用层：报表、指标、管理端看板 | `ads_` |
| DIM | `dim` | 维度表：城区、运动类型、日期等 | `dim_` |

当前后端只有 `src` 层；数据仓库建设时按本表建 schema。

## 四、时间粒度与表后缀（ODS 及以上各层）

| 时间粒度 | 增量后缀 | 全量后缀 | 说明 |
| :--- | :--- | :--- | :--- |
| 小时 | `_hrs` | `_hrs_f` | 小时级增量 / 小时级全量快照 |
| 天 | `_di` | `_df` | 天级增量 / 天级全量 |
| 周 | `_wk` | `_wk_f` | 周级增量 / 周级全量快照 |
| 月 | `_mo` | `_mo_f` | 月级增量 / 月级全量快照 |
| 季度 | `_q` | `_q_f` | 季度级增量 / 季度级全量快照 |
| 年 | `_yr` | `_yr_f` | 年级增量 / 年级全量快照 |
| 无周期（全量） | - | `_f` | 非分区全量表 |
| 拉链表 | - | `_zip` | 记录历史变更 |

`src` 层是线上实时读写的业务表，不加粒度后缀。

**分区字段**：数仓各层默认按运动日期分区，统一叫 `sport_date`，格式 `YYYYMMDD`。业务库的大表（轨迹点）按记录时间 `record_time` 做范围分区。

## 五、字段命名关键字

| 关键字 | 含义 | 实例 |
| :--- | :--- | :--- |
| `_id` | 主键、外键 | `user_id`、`territory_id` |

| `_amt` | 金额，**单位：分**，整数 | `order_amt`、`price_amt` |
| `_qty` | 数量 | `energy_qty` |
| `_rate` | 比例、费率、占比 | `refund_rate` |

## 七、迁移文件

- 放在 `server/migrations/`，文件名 `NNNN_说明.up.sql` / `.down.sql`，按编号顺序执行，执行过的不能再改。
- 新建表在同一个迁移里写全表注释和字段注释。
- 删字段、改类型分两步上线（先兼容读写，再删）。
