# 圈圈 Loopland · 设备接入预留说明

现在圈圈只用自己这一套数据来源，不接任何第三方手表、手环或运动平台：

| 来源 | 覆盖 |
|---|---|
| 手机 GPS | 跑步、健走、骑行、徒步（圈地的依据） |
| 手机摄像头 + 本机姿态识别（AI 跟练） | 力量、瑜伽、跳绳 |
| 场馆扫码签到 | 球类等场馆运动 |
| 开放平台（合作场馆的系统、闸机） | 场馆签到、占场 |

以后如果推出**圈圈自己的运动设备**（手环、心率带、智能跳绳等），按下面这些已经留好的口子接进来，不需要改数据结构。

---

## 一、总开关：`features.wearable`（默认关闭）

- 服务端 `server/config.yaml`：`features.wearable: false`（环境变量 `LOOPLAND_FEATURE_WEARABLE=1` 打开）。
- `GET /v1/config/features` 返回 `"wearable": true | false`，App 和管理端据此决定是否显示穿戴设备相关的界面。
- **关着时（现在）**：
  - App 隐私授权页、设置页不出现「运动健康数据」开关，不申请用不到的授权；
  - 管理端建赛事时不出现「要求穿戴设备数据」，赛事列表不显示「穿戴设备」列（已有赛事设过的照常显示）。
- **打开后**：上面这些界面直接恢复，不用改代码。

## 二、已经留好的口子

| 口子 | 在哪 | 现在的状态 |
|---|---|---|
| 运动上传带设备信息 | `POST /v1/activities` 的 `wearable`（`docs/api/v1.md`），存到运动记录的 `wearable_json` | 字段在，App 现在不传 |
| 轨迹点的心率、步频、数据来源 | 轨迹点 `hr`、`cad`、`src`（表 `src.src_act_loop_track_point` 的 `heart_rate`、`cadence`、`source`） | 字段在，`src` 现在是 `gps` / `mock` |
| 用户的健康数据授权 | `consents.health`（`POST /v1/me/consents`） | 字段在，开关关着时界面不出现 |
| 要求穿戴设备数据的赛事 | 赛事 `requires_wearable`，结算时判断这次运动是否带 `wearable`（`docs/api/v2-2-社区.md`） | 逻辑在，管理端选项随开关隐藏 |
| 风控规则 | 风控规则 `require_wearable_for_events` | 规则在 |
| 设备 / 场馆推送数据 | 开放平台 `/open/v1`（签名、回调、幂等；`docs/api/v2-5-商户商品与开放平台.md`） | 已上线，场馆在用 |

## 三、以后接入自有设备的两条路

1. **设备直连手机（蓝牙）**：跑步时 App 连上圈圈手环 / 心率带，实时把心率、步频写进每个轨迹点（`hr`、`cad`），上传时带 `wearable: {"brand":"loopland","model":"...","serial":"..."}`。适合跑步、骑行时的实时数据。
2. **设备云端同步**：设备先同步到圈圈的设备服务，再按开放平台的方式（签名接口 + 幂等）写入运动记录。适合跳绳次数、游泳、室内运动这类不靠手机 GPS 的数据。

接入时要定的规则（届时再定）：
- 设备数据能否单独产生运动记录、能否圈地（建议：带完整 GPS 轨迹的才能圈地；只有心率 / 次数的只计能量和成就）。
- 设备身份校验（序列号绑定账号、签名），防止伪造设备数据刷能量。
- 游泳等现在没有记录方式的运动，在有设备后再开放（能量规则 `swim` 已经在玩法配置里）。
