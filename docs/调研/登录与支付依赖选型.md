# Go 语言：统一登录 + 统一支付 依赖选型

> 数据查询时间：2026-11-20（GitHub Star 数和最近提交时间来自 GitHub API）。

## 一、结论速览

**没有一个库能把登录和支付全部包圆，但用 2～3 个成熟依赖就能覆盖你列的所有需求。**

| 需求 | 推荐依赖 | 说明 |
|---|---|---|
| 统一登录（一站式） | **Casdoor**（自部署身份认证服务） | 开箱即用，支持短信、微信、Google 等，自带后台 |
| 统一登录（库方式） | **markbates/goth** + 短信 SDK + 一键登录 SDK | 自己写账号体系，灵活但工作量大 |
| 统一支付（国内） | **go-pay/gopay** | 一个库覆盖微信、支付宝、抖音、PayPal、Apple 等 |
| 信用卡（国际卡） | **stripe/stripe-go** | 需要境外主体，见下文 |

## 二、统一登录

### 方案 A：Casdoor（推荐，最快）

- 仓库：https://github.com/casdoor/casdoor （约 1.5 万 Star，持续活跃）
- Go SDK：https://github.com/casdoor/casdoor-go-sdk
- 形态：独立部署的身份认证服务（Go + React），支持 OAuth2 / OIDC。你的业务后端只负责对接它。
- 支持的提供商类型：**OAuth 第三方登录**（微信、QQ、Google、GitHub 等）、**短信**（阿里云、腾讯云等）、邮件、验证码、**支付**（支付宝、微信支付、PayPal）、MFA 等。
- 优点：注册、登录、绑定手机号、账号合并、管理后台都是现成的，国人团队维护，国内渠道支持好。
- 缺点：多部署一个服务；**运营商"一键登录"一般需要自己对接**（见下文）；深度定制 UI 要改它的前端。

同类可选：**Zitadel**（约 1.6 万 Star）、**Ory Kratos**（约 1.4 万 Star）。这两个都是 Go 写的，偏海外生态，国内的短信和微信渠道要自己扩展，所以国内项目首选 Casdoor。

### 方案 B：自己拼装（库方式）

| 登录方式 | 依赖 | 备注 |
|---|---|---|
| 第三方 OAuth（微信、Google、Apple、钉钉、飞书、TikTok 等） | **github.com/markbates/goth**（约 6.6k Star） | 一套统一接口，自带 `wechat`、`wecom`、`google`、`apple`、`dingtalk`、`lark`、`tiktok` 等 60 多个 provider |
| 微信生态（公众号网页授权、小程序登录） | **github.com/silenceper/wechat**（约 5.3k Star）或 **ArtisanCloud/PowerWeChat** | 小程序 `code2session`、公众号网页授权这类场景，goth 不覆盖 |
| 手机短信验证码 | 阿里云 **alibabacloud-go/dysmsapi-20170525**，或腾讯云 **TencentCloud/tencentcloud-sdk-go**（sms 模块） | 验证码生成、存储和限流用 Redis 自己实现 |
| 一键手机登录（运营商取号） | 阿里云号码认证 **alibabacloud-go/dypnsapi-20170525**（`GetMobile` 接口） | 也可以用极光认证、创蓝闪验、腾讯云号码认证等，它们的服务端都是 HTTP API |
| 会话 / Token | `github.com/golang-jwt/jwt/v5` | 登录后统一签发自家 JWT |

### 各登录方式的前置条件（容易踩坑）

1. **手机短信**：需要在阿里云或腾讯云申请**短信签名和模板**（要企业资质），按条计费。必须做防刷：图形验证码、单号码和单 IP 限频、每日上限。
2. **一键手机登录**：
   - 流程是：客户端 SDK 先拿到运营商 Token（用户必须在授权页点确认），后端再用 Token 调 `GetMobile` 换取手机号。
   - Token 有效期很短，而且只能用一次：中国移动 2 分钟，联通 30 分钟，电信 10 分钟。
   - **主要用在 App**，必须集成 iOS 或 Android SDK。也有 H5 版本，但要求用户开着移动数据网络，Wi-Fi 下用不了，所以网页端一般用短信验证码兜底。
   - 阿里云条款写明：不得模拟或绕过用户授权。
3. **微信登录**：
   - PC 网页扫码登录：要在**微信开放平台**创建"网站应用"，并完成开发者资质认证（收费）。
   - 微信内打开的网页：用**公众号网页授权**（需要服务号）。
   - 小程序：用 `wx.login` 加服务端 `code2session`。
   - App：用开放平台"移动应用"。
   - **多端账号打通要靠 `unionid`**，这些应用必须绑定在同一个开放平台账号下。
4. **Google 登录**：大陆用户直连 Google 不稳定，只适合海外用户或者有海外业务的场景，国内用户不要把它当主要入口。另外，iOS App 如果提供了第三方登录，按苹果审核规则通常还要同时提供 **Sign in with Apple**（goth 已支持）。

### 账号体系建议（关键设计）

```
users            用户主表（id, nickname, avatar, created_at）
user_identities  登录方式表（user_id, provider, provider_uid, unionid, credential...）
                 provider 取值：phone / wechat / google / apple ...
```

一个用户可以绑定多种登录方式，以手机号作为主要标识。第三方首次登录时引导用户绑定手机号，这也符合国内网络实名要求。

### 统一接口示例（方案 B）

```go
package auth

import "context"

// Identity 是各登录渠道返回的统一身份
type Identity struct {
	Provider    string // phone / wechat / google / apple
	ProviderUID string // 手机号 / openid / sub
	UnionID     string // 微信 unionid（可选）
	Nickname    string
	Avatar      string
}

// Provider 统一登录接口
type Provider interface {
	Name() string
	// Authenticate 用客户端传来的凭证（验证码、OAuth code、一键登录 token）换取身份
	Authenticate(ctx context.Context, credential map[string]string) (*Identity, error)
}

// Registry 统一入口
type Registry struct{ providers map[string]Provider }

func (r *Registry) Login(ctx context.Context, name string, cred map[string]string) (*Identity, error) {
	p, ok := r.providers[name]
	if !ok {
		return nil, ErrUnknownProvider
	}
	return p.Authenticate(ctx, cred)
	// 之后：查 user_identities → 找到或创建 user → 签发 JWT
}
```

一键登录的实现示意（阿里云 `GetMobile`）：

```go
import (
	openapi "github.com/alibabacloud-go/darabonba-openapi/v2/client"
	dypns "github.com/alibabacloud-go/dypnsapi-20170525/v2/client"
	"github.com/alibabacloud-go/tea/tea"
)

type OneClickProvider struct{ cli *dypns.Client }

func NewOneClick(ak, sk string) (*OneClickProvider, error) {
	cli, err := dypns.NewClient(&openapi.Config{
		AccessKeyId:     tea.String(ak),
		AccessKeySecret: tea.String(sk),
		Endpoint:        tea.String("dypnsapi.aliyuncs.com"),
	})
	return &OneClickProvider{cli: cli}, err
}

func (p *OneClickProvider) Name() string { return "oneclick" }

func (p *OneClickProvider) Authenticate(ctx context.Context, c map[string]string) (*Identity, error) {
	resp, err := p.cli.GetMobile(&dypns.GetMobileRequest{AccessToken: tea.String(c["token"])})
	if err != nil {
		return nil, err
	}
	if tea.StringValue(resp.Body.Code) != "OK" {
		return nil, fmt.Errorf("getmobile: %s", tea.StringValue(resp.Body.Message))
	}
	mobile := tea.StringValue(resp.Body.GetMobileResultDTO.Mobile)
	return &Identity{Provider: "phone", ProviderUID: mobile}, nil
}
```

> 注：SDK 的具体版本号和字段名以 `go get` 后的实际代码为准。

## 三、统一支付

### 1. go-pay/gopay（国内首选，一个库搞定大部分渠道）

- 仓库：https://github.com/go-pay/gopay （约 5.8k Star，Apache-2.0 协议，持续更新）
- 安装：`go get github.com/go-pay/gopay`
- 覆盖渠道：**微信支付 V3**（推荐使用，V2 已不推荐）、**支付宝**（含 V3 版本）、抖音支付、QQ 钱包、招商银行聚合支付、通联支付、拉卡拉、扫呗、**PayPal**、**Apple 内购校验**。
- 微信支付覆盖 JSAPI、小程序、App、H5、Native 扫码、退款、回调验签、商家转账等。
- 注意：从 v1.5.119 起默认开启 TLS 证书校验，沙箱或自签证书环境需要手动配置。

**备选或补充（官方或单一渠道 SDK）：**

| 渠道 | 依赖 | 说明 |
|---|---|---|
| 微信支付 | `github.com/wechatpay-apiv3/wechatpay-go` | **微信官方** APIv3 SDK（约 1.3k Star）。最近一次提交在 2025 年 7 月，更新频率较低 |
| 支付宝 | `github.com/smartwalle/alipay/v3` | 社区维护，约 2.1k Star，功能完善，支持公钥证书模式 |

### 2. 信用卡：stripe/stripe-go

- 仓库：https://github.com/stripe/stripe-go （Stripe 官方维护，非常活跃）
- 支持 Visa、Mastercard、Amex、JCB 等国际卡，以及 Apple Pay、Google Pay；Stripe 本身也能收支付宝和微信支付，主要面向海外用户。
- **重要限制**：Stripe 通常需要**境外主体**开户（比如香港、新加坡或美国公司），一般不直接支持中国大陆企业收国内用户的款。请以 Stripe 官网的开户要求为准。

**国内收"信用卡"其实不用单独接**：国内用户的银联信用卡可以直接绑在微信或支付宝里付款，接好微信和支付宝就已经覆盖了。只有在需要收**境外 Visa/Master 卡**（比如海外用户）的时候才需要 Stripe，或者 PayPal（gopay 已包含），或者国内持牌的跨境收单机构。

### 3. 商户资质前置条件

| 渠道 | 需要什么 |
|---|---|
| 微信支付 | 企业或个体工商户营业执照、对公账户、已备案的域名；API 证书和 APIv3 密钥 |
| 支付宝 | 企业支付宝账号，签约对应产品（电脑网站支付、手机网站支付、App 支付等）；应用公私钥或公钥证书 |
| Stripe | 境外主体和境外银行账户 |
| PayPal | 企业 PayPal 账户 |
| Apple 内购 | **App 内售卖虚拟商品必须走苹果内购**，不能引导到微信或支付宝，否则审核会被拒 |

### 统一支付接口示例

```go
package payment

import (
	"context"
	"net/http"
)

type Channel string

const (
	WechatNative Channel = "wechat_native" // PC 扫码
	WechatJSAPI  Channel = "wechat_jsapi"  // 公众号/小程序
	WechatH5     Channel = "wechat_h5"
	AlipayPage   Channel = "alipay_page"   // PC 网页
	AlipayWap    Channel = "alipay_wap"    // 手机网页
	StripeCard   Channel = "stripe_card"   // 国际信用卡
	PayPal       Channel = "paypal"
)

type CreateOrderReq struct {
	OrderNo   string // 你自己的订单号（幂等键）
	AmountFen int64  // 金额统一用"分"，避免浮点误差
	Currency  string // CNY / USD
	Subject   string
	OpenID    string // 微信 JSAPI 需要
	ClientIP  string
	NotifyURL string
	ReturnURL string
}

type CreateOrderResp struct {
	PayURL    string            // 跳转链接（支付宝 page/wap、Stripe Checkout、PayPal）
	QRCode    string            // 二维码内容（微信 Native）
	SDKParams map[string]string // 前端调起参数（微信 JSAPI/App）
}

type Notify struct {
	OrderNo   string
	TradeNo   string // 渠道流水号
	AmountFen int64
	Paid      bool
}

type Provider interface {
	Create(ctx context.Context, ch Channel, req *CreateOrderReq) (*CreateOrderResp, error)
	Query(ctx context.Context, orderNo string) (*Notify, error)
	Refund(ctx context.Context, orderNo string, amountFen int64, reason string) error
	// ParseNotify 校验回调签名并解析，必须验签
	ParseNotify(r *http.Request) (*Notify, error)
}

// 实现：WechatProvider / AlipayProvider（基于 gopay）、StripeProvider（基于 stripe-go）
```

### 支付系统必须做好的几件事

1. **以回调和主动查询为准**：不能信任前端返回的"支付成功"，一定要收到渠道回调并**验签**后，才把订单改成已支付。
2. **幂等**：回调会重复推送，按订单号加锁或者用状态机，确保只发货一次。
3. **金额校验**：回调里的金额必须和订单金额一致。
4. **对账**：每天下载渠道账单和本地订单核对。微信、支付宝都提供账单下载接口，gopay 也支持。
5. **掉单补偿**：定时任务查询"支付中"的订单。
6. **密钥安全**：证书和私钥放在 KMS 或密钥管理系统里，不要写进代码仓库。

## 四、推荐组合（针对你的图片社区项目）

```
登录：Casdoor（短信 + 微信 + Google/Apple）+ 自接阿里云一键登录（App 端）
支付：gopay（微信 V3 + 支付宝）+ stripe-go（海外信用卡，可后期再加）
其他：Redis（验证码/限流/幂等锁）、golang-jwt（自家 Token）
```

如果你倾向全部自研、不想多部署一个服务，就用方案 B：goth + silenceper/wechat + 阿里云短信和号码认证 SDK + gopay + stripe-go。
